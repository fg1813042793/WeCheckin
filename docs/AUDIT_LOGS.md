# 登录安全与操作审计

## 数据与结果

审计记录存储在既有 `logs` 表。迁移扩展结构，旧数据保留 `legacy-{id}` 事件标识和 `unknown` 结果；不能从现在的代码反推旧记录一定成功。

每次受审计请求先记录一条 `unknown` 尝试，业务返回后使用同一 `eventId` 完成结果。结果基于业务 `code` 和服务层原因，不依赖 HTTP 200。可用结果为 `success`、`failure`、`blocked`、`partial`、`accepted`、`unknown`。异步执行/重试只表示请求受理，最终状态仍以关联的任务运行或通知投递记录为准。

请求采集在认证和权限中间件之前安装，因而认证失败和权限拦截也会保留。只有经过认证的身份才成为实际操作者；`attemptedAccount` 是登录者输入的、未验证的账号，不代表已认证用户。

匿名请求访问受保护操作而被拦截时，归入登录安全日志的 `access_denied` 事件，避免因没有操作人 ID 被普通数据范围隐藏。登录会话保存失败时返回失败结果，不再把仅通过密码校验当作完成登录。

批量操作分别记录 `targetIds`、`requestedCount` 和服务端可确认的 `affectedCount`。目标列表最多1000项；超过时由请求数量与列表长度体现截断。不能把请求数量当作删除成功数量。未返回或未能可靠确认的影响数量显示为未记录。

明确的导出请求也记录返回数据的目标 ID，最多1000项；当导出条数超过已记录 ID 数量时，详情明确提示目标列表不完整。导出数量不会被当作请求目标数量。

请求详情还包含 `browser/deviceType/platformType`，与问卷答卷复用同一套 UA 识别，完整 UA 仅在详情提供。访问日志中的验证码、票据、秘密字段和表单正文同样脱敏；系统配置等不透明 key/value 操作不记录请求体。

## 模块覆盖

| 模块 | 审计事件 | 其他记录关联 |
| --- | --- | --- |
| Admin、客户端、H5App 认证 | 密码、验证码失败、免登、绑定、退出、改密、强制下线；包括兼容客户端密码入口 | 登录原因码、认证后的操作者 |
| 用户、管理员、角色、权限 | 创建、修改、状态、密码重置、删除、授权及数据范围、明确导出请求 | 安全字段和授权关系快照 |
| 组织与审批身份 | 部门、岗位、审批身份任命变更 | 任命对象与身份 |
| 问卷、考试及答卷 | 创建、编辑、发布状态、删除、答卷导出/批量删除、题库和资源变更 | 问卷/考试/答卷 ID |
| 流程管理 | 定义修改、发布、回滚、实例发起/撤回/取消、任务处理、表单修订 | 保留流程历史，审计只关联实例或任务 ID |
| 定时任务 | 创建、配置、启停、手工运行、重试、取消、运行记录删除 | `scheduled_task_run` |
| 通知 | 手工发送、测试、重试、删除、样式修改 | 既有投递记录，保留部分失败信息 |
| 系统与钉钉配置 | 配置保存、账号绑定和绑定状态、绩效关键动作 | 秘密配置只记录变更标记 |
| 字典、内容与反馈 | 增删改、状态更新、反馈处理与补充 | 复用反馈消息时间线及业务历史 |

普通查询、验证码图片获取、校验/预览等无副作用计算，以及普通已读标记不生成成功操作审计；认证/授权拒绝仍会记录。自动后台执行的完整过程保留在既有运行日志中，不重复复制到操作表。

用户、管理员、角色的原本浏览器缓存 CSV 导出现在使用明确的服务端 `/export` 列表读取，保持原列表的数据范围与当前筛选页范围。服务端审计记录发出数据的数量；无法据此证明浏览器最终将文件保存到磁盘。

## 快照边界与脱敏

关键资源的更新/删除可附带请求前后快照，字段由服务端白名单控制，失败请求不附加快照内容。快照读取在业务事务外，可能观察到并发修改；页面明确标为“请求前后快照”，不能把全部差异直接归因于该操作者。新建对象记录返回的目标 ID，不复制完整对象内容。

快照最多20个目标，关联关系与字段大小受限；超时、读取失败、超限均记录固定的快照不可用原因而不改变业务结果。密码、验证码内容、授权码、绑定票据、Token、密钥、完整答案、Schema、正文均不作为审计值。敏感配置只保留 `[已隐藏]` / `[已变更]`。请求体、结果体、UA 和批量目标都有采集边界，日志不承担完整业务数据备份职责。

普通配置采用明确白名单：管理员/H5 登录验证码启用开关、单点登录、自助绑定、通知开关、会话有效期、通知方式，以及企业配置的启用/通知开关与通知方式。值必须通过布尔、正时长或枚举校验，不能仅因字段名像公开开关就记录任意字符串；其他配置和非法值仍隐藏。采集器与序列化器都会校验。Admin 将配置键和已有实体字段转换为中文名称，保留原键 tooltip；历史隐藏标记不还原，缺失旧值不推断为“关闭”或“未设置”。

快照状态通过独立的 `snapshotStatus` / `snapshotReason` 保存，不占用业务操作的结果和原因字段：

| snapshotStatus | 说明 |
| --- | --- |
| pending | 请求已开始，快照或最终记录尚未完成 |
| recorded | 已记录字段差异，可能含脱敏值 |
| unchanged | 已采集字段无差异；不能代表所有业务字段均未变化 |
| not_applicable | 登录、导出、仅记录目标的新建或关联运行记录等不采集前后字段的操作 |
| not_configured | 此修改操作或配置键尚未接入快照采集 |
| operation_failed | 业务失败或被拦截，未附加快照值 |
| unavailable | 读取失败、超时、超限或序列化失败；具体闭集原因码在 snapshotReason |
| legacy_unknown | 旧记录未保存快照状态，不猜测当时缺失的原因 |

新日志不再输出内部 `privateConfigChanged` 字段。旧日志仍保留原数据，但页面将它转为说明：只表示配置发生变化，不表示某个开关已经开启。旧日志有实际差异时仍显示差异；已有隐藏值不能从这条日志恢复。

审计写入同步且有超时，使用独立的受限结束上下文，客户端取消不会直接丢失最终日志。写库失败输出带 `eventId/requestId` 的已脱敏 `[AUDIT_WRITE_FAILED]` 备用日志，须纳入部署日志采集和告警。它不具备与全部业务表写入的原子事务保证；未正常完成的尝试保留 unknown，不能伪造成功。服务崩溃且数据库和日志采集同时不可用时仍可能丢失事件。

## 查询与授权

| 接口 | 权限 | 说明 |
| --- | --- | --- |
| `GET /api/v2/admin/logs`、`/logs/{id}` | `admin:api:log:list` | 操作日志，沿用实际操作者的数据范围 |
| `GET /api/v2/admin/login-logs`、`/login-logs/{id}` | `admin:api:log:security` | 独立安全日志授权，包含匿名失败尝试 |
| `GET /api/v2/admin/logs/export` | `log:list` + `log:export` 对应 API 权限 | 最多1000条，返回真实匹配总数 |
| `GET /api/v2/admin/login-logs/export` | `log:security` + `log:security-export` 对应 API 权限 | 最多1000条，不沿用普通操作者范围 |
| `DELETE /api/v2/admin/logs`、`/logs/{id}` | `log:list` + `log:delete` 对应 API 权限 | 批量/单条删除可见的操作日志 |
| `DELETE /api/v2/admin/login-logs`、`/login-logs/{id}` | `log:security` + `log:security-delete` 对应 API 权限 | 批量/单条删除登录日志 |

查询过滤：`search/source/module/action/outcome/actorId/ip/startTime/endTime/page/pageSize`。普通分页最多100条，时间为毫秒时间戳或带时区的 RFC3339，日期边界由服务端明确解析。列表/导出不加载长变更快照与原始 UA；详情在同一权限边界内返回它们。导出排除当前未完成的导出事件自身，避免污染统计。

对应菜单动作：`admin:menu:log:security`、`admin:menu:log:export`、`admin:menu:log:security-export`、`admin:menu:log:delete`、`admin:menu:log:security-delete`。查看、导出与删除分别授权；超级管理员按既有规则可见。日志内容不提供编辑接口，删除需经过明确确认；没有自动删除任务或一键清空入口。

批量删除使用 JSON 请求体 `{"ids":[41,42]}`，每次必须提交 1–100 个不重复的正整数；单条删除仅使用路径 ID，不接受请求体。返回 `{"code":0,"msg":"success","data":{"deletedCount":2}}`。服务端在同一事务中按分类、查看权限及操作日志数据范围锁定全部目标，再执行删除；包含不存在、其他分类或不可见记录时整批拒绝，不返回部分成功。删除失败回滚，当前删除请求自己的审计事件不会被删除。删除操作本身记录 `audit/delete`、目标 ID 与实际影响数量。

Admin 支持当前页勾选批量删除和行内删除，删除前显示类别与数量；取消不发送请求，失败保留勾选供重试，成功刷新列表，末页删空后退回有效页。翻页、筛选变动、刷新或切换日志类别会清空勾选。旧的无操作者服务入口仍拒绝删除/清空。

## 来源 IP

服务默认仅信任连接对端，不信任任意请求携带的 `X-Forwarded-For/X-Real-IP`。在反向代理部署中，通过 `server.audit_trusted_proxy_cidrs` 或逗号分隔环境变量 `WECHECKIN_SERVER_AUDIT_TRUSTED_PROXY_CIDRS` 明确指定受控代理网段。不允许 `0.0.0.0/0` 或 `::/0`。未配置时，看到代理 IP 是预期行为；不会把未经验证的转发头当作客户端地址。变量名为兼容既有部署保留，配置会统一影响访问日志、登录会话、审计日志以及所有通过 `c.ClientIP()` 写入的业务 IP 字段。

## 升级与回滚

1. 备份 `logs` 表，评估加列/索引的维护窗口。
2. 使用项目迁移工具执行 `20261028180000_expand_audit_logs.sql`。迁移可重跑，保留原字段与旧日志；主服务不会自动迁移。
   快照状态优化还需执行 `20261029150000_add_audit_snapshot_status.sql`，再发布后端。该迁移只添加状态/原因列，旧行默认 `legacy_unknown`，不会回填或改写旧值。
3. 删除功能需执行 `20261106110000_add_audit_log_delete_permissions.sql`，该迁移只注册新权限并停用旧 `log:del` 兼容权限，不复制历史授权。发布后端和 Admin，配置可信代理，并给需要的角色显式分配相应查看、导出或删除菜单/API 权限；重新登录刷新权限。
4. 验证错误密码、验证码失败、权限拒绝、角色修改、答卷导出/删除、异步任务受理及日志读取权限；监控 `[AUDIT_WRITE_FAILED]`。
5. 应用回滚时保留新增字段和审计数据，不执行删列。旧版本仍可写旧字段，读取兼容逻辑会将这种日志显示为 unknown；旧版本的删除能力和审计缺口会恢复，因此不应把回滚视为同等安全配置。

开发验证使用临时 MySQL `audit_verify`，不执行生产迁移。可设置 `WECHECKIN_AUDIT_TEST_DSN` 指向专用 localhost:18306 数据库运行存储集成测试；常规测试不连接该数据库。
