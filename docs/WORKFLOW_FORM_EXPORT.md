# 汇总页导出表单

钉钉 H5 的“流程审批 → 汇总”在工具栏“批量导出”后和每条记录“导出”后提供“导出表单”。两种入口共用格式选择和原有导出权限；工具栏导出当前页勾选记录，未选择时禁用，行内入口只导出当前记录。

## 内容

- 现有“导出/批量导出”生成完整记录，继续包含流程信息、表单及审批记录。
- “导出表单”仅包含一行表单标题、表单分组、字段、明细行和保存的计算/评分结果。
- 纯表单文件不单独输出系统的流程名称、申请编号、版本、状态、发起人、操作人、发起/完成时间元信息行及审批任务记录；发起人名称仅用于标题和文件/工作表命名。
- “上级评分”“HRBP评价”等实际表单字段照常导出。按数据来源区分系统信息与表单内容，不按字段标签删除同名字段。
- 每条记录读取自身绑定版本的表单结构；汇总列表的“列设置”仅影响列表展示，不改变导出表单的内容。

## 文件组织

- Excel：单条一个工作表；批量一个工作簿，每条记录一个独立工作表。
- 工作表名和首行标题统一使用“发起人用户名-当前管理名称”，例如“Foster-MH-通用绩效考评单”，完整记录和纯表单导出均适用。每次导出在权限校验后批量读取当前管理名称，改名无需重新发布流程。用户名优先使用记录的发起人名称，缺失时尝试名称映射；都不存在时仅使用管理名称。工作表名遵守 Excel 的 31 字符限制并替换非法字符，首行标题保留完整名称。
- 已停用流程仍可读取当前管理名称；定义已删除、不存在或管理名称为空时回退到实例原有名称。读取失败会返回错误，不使用缓存旧名冒充最新名称。
- PDF、Word：单条直接下载；批量各自生成文件并打包 ZIP。
- PDF、Word 的文档标题同样带发起人用户名。纯表单文件使用该标题命名；批量不同标题使用“表单导出”。工作表及 ZIP 内的同名文件追加序号，不使用系统内部流程编号。
- 名称更新仅作用于导出视图，不回写实例名称快照，表单结构、字段和审批记录仍取自该申请的历史版本。已经下载的文件不会随后台改名自动更新，需要重新导出。
- 复用现有每次最多 50 条记录和 64 MiB 导出体积限制，不改变审批、表单或流程状态。

## API

`GET /api/v2/dingtalk/h5/workflows/summary/export`

| 参数 | 含义 |
| --- | --- |
| `instanceIds` | 逗号分隔的实例 ID |
| `format` | `xlsx`、`pdf` 或 `docx` |
| `content` | 可选，`full` 完整记录；`form` 仅表单。缺省/空字符串等同 `full`，其他值返回参数错误 |

两种导出模式均执行现有身份、导出权限及实例可见范围校验；任何选中实例不可见时拒绝整批导出。无需新增数据库字段或权限项。

## 验证

- H5 调用契约：`cd h5app && pnpm check:workflow-summary-export`。
- 服务端及 HTTP：`cd backend && GOCACHE=$PWD/../.cache/go-build go test ./internal/service/dingtalkh5/workflowsummary ./internal/modules/workflow/transport/httpclient ./internal/modules/workflow/transport/httperror -count=1`。
- 覆盖完整/纯表单、三种格式、单条/批量、历史版本、嵌套分组、标题冲突、无权限和非法参数。
- 管理名称同步回归：`cd backend && GOCACHE=$PWD/../.cache/go-build go test ./internal/service/dingtalkh5/workflowsummary ./internal/modules/workflow/infrastructure ./internal/modules/workflow/transport/httpclient -count=1`。覆盖未重新发布时改名、连续改名、批量读取、停用定义、缺失名称回退、读取失败和权限校验顺序；相关测试及实际导出样例通过。后端全量测试仍有既有钉钉配置文案、审计分类及受跟踪配置检查失败。
- 此修复需要后端服务更新后生效。更新后刷新 H5、重新导出即可，不需要重新发布流程。
