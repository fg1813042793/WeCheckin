# 历史表单导入规则

在 Admin 的“流程设计器 → 流程配置 → 导入规则设置”启用预设，然后保存流程配置。规则复用现有即时生效配置，后续加载 H5 发起表单时即可使用，无需重新发布流程，也无需新增数据库表。

## 设置方式

导入规则卡片保留启用开关；“导入方式”“字段映射”和“使用说明”可分别展开。已有有效规则默认收起并展示摘要，明细列映射也默认折叠。首次启用、切换为自定义映射或出现校验错误时，会展开相应设置区域。收起内容不会清空配置，也不会触发保存。

| 配置 | 说明 |
| --- | --- |
| 启用预设导入规则 | 默认关闭；关闭或没有配置时，H5 保留原三步手工导入向导 |
| 来源方式 | 用户选择一条历史记录后直接导入；或点击导入后自动取最近一条符合条件的记录 |
| 来源状态 | 默认仅已完成，也可选择全部可见状态 |
| 字段方式 | 按同名且类型兼容的字段导入；或手工配置来源字段 → 当前目标字段 |
| 明细列映射 | 明细表可配置一层来源列 → 目标列；不配置时沿用同名列规则 |
| 覆盖已有内容 | 默认只填空字段；开启后允许覆盖目标字段已填写的内容 |

“最近一次”按发起时间倒序、记录 ID 倒序选取第一条，不按完成时间推断。历史记录范围保持为本流程、当前用户本人发起且可见的申请；不提供跨用户、跨流程复制。

例如，将历史“下月目标”导入当前“本月目标”：选择自定义映射，配置这两个明细字段；如果两边列编码不同，再配置“目标内容 → 目标内容”“权重 → 权重”等列映射。来源字段/列与目标字段/列各不能重复。

启用后，“用户选择”模式只保留历史记录选择，不再进入配置和预览步骤；“最近一次”模式直接读取并应用最近记录。导入只预填当前表单，不自动提交流程。

## 兼容与保护

- 规则字段基于当前流程表单设置。已发布流程继续验证活动发布版本的字段；新字段需要先发布后才能用于即时规则。
- 每条历史记录按自身的发布版本解析。不存在、不可写、不兼容、空值或无效选项按安全导入逻辑处理并给出结果反馈；不能因为有预设就绕过字段权限或复制计算字段。
- 默认只填空字段。管理员允许覆盖时，H5 显示覆盖策略；零个可导入字段不会显示导入成功。
- 读取失败、无符合条件的记录或无效规则不会静默切换到手工向导。关闭弹窗、切换流程/规则后，旧请求不得继续写入当前表单。
- 关闭规则保留配置草稿，启用时重新校验。切换到同名字段模式不使用保留的手工映射。
- 旧流程没有 `historyImport` 时维持现有行为；历史发布版本的 JSON 不会被改写。

## 接口契约

既有流程保存请求的 `draft.historyImport` 和已发布定义响应的 `historyImport` 使用同一结构：

```json
{
  "enabled": true,
  "sourceMode": "select_history",
  "sourceStatus": "completed",
  "mappingMode": "mapping",
  "overwrite": false,
  "mappings": [
    {
      "sourceKey": "next_month_goals",
      "targetKey": "current_month_goals",
      "columns": [{"sourceKey": "goal", "targetKey": "goal"}]
    }
  ]
}
```

sourceMode 为 `select_history/latest_history`，sourceStatus 为 `completed/all`，mappingMode 为 `same_key/mapping`。启用时省略的模式采用新编辑器默认值；显式映射模式需要1至100条字段映射，明细列映射配置后需要1至100条。同名字段模式保留但不执行手工映射。

规则保存于既有 `definition_start_config_json`，改变时更新 `startConfigRevision`；管理员仍需原有流程编辑权限。H5 历史读取、按钮权限、发起权限及最终提交校验保持原有边界。
