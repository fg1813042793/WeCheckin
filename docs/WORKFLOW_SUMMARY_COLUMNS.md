# 汇总表单列

基础列可勾选“流程名称、申请编号、操作人、版本、完成时间”。申请编号默认显示；取消勾选可隐藏，选择会保存在当前浏览器，恢复默认后重新显示。

汇总筛选中的“管理名称”来自当前已发布流程定义并按 `definitionId` 精确过滤；“流程名称”继续匹配申请创建时保存的用户显示名称快照。管理名称修改后刷新页面即可使用新名称筛选，不会因历史显示名称不同而漏查。

“列设置”的流程字段下拉框展示流程的管理名称（`name`），字段面板标题使用相同名称；按所选流程当前发布表单提供字段。普通字段读取该申请保存的表单数据，不在不同流程间按名称猜测或匹配。

`name` 从当前流程定义元数据读取，后台修改管理名称后刷新 H5 即可取得新名称，无需重新发布流程。表单字段仍来自发布版本，修改名称不会切换到未发布的表单草稿。

## 跨流程汇总列

在“列设置 → 汇总列 → 新增汇总列”填写列名，再逐行选择流程管理名称、适用版本和来源字段。例如，“最终分档”可同时配置通用流程的最终分档、William 专用流程的最终分档及实习生流程的综合分档。表格只显示一个自定义列头，每条记录严格按所属流程选择对应字段，不按名称猜测匹配。

- 支持新增、编辑、取消、隐藏、恢复显示及删除。新建时默认勾选“用此列替换已勾选的来源字段”，避免与已有单流程列重复；可以取消该选项。编辑时默认保留原有其他列选择。
- “默认规则”使用该流程当前发布字段。需要不同历史字段时选择具体版本；版本选项来自当前发布版本、当前列表的记录和已保存来源。明确版本的映射优先于默认规则。
- 历史字段通过当前页可见记录的汇总详情接口读取，后端照常校验可见范围。当前页没有该版本记录时，先筛选或翻页到对应记录再配置。相同流程/版本只读取一次，权限版本变化时清除内存缓存；后端拒绝或响应版本不符时不回退到其他流程或默认规则。
- 每列必须有列名及至少一个完整来源，同一流程/适用版本不能重复配置。最多 20 列、每列最多 50 个来源。字段类型不同会提醒核对业务含义、单位和等级，用户明确确认的映射仍可保存。
- 已保存值优先，计算字段沿用该来源自己的公式、选项计算值和显示格式。补算保留标记；无来源、字段不可用、历史版本未加载或数据不足时显示 `-`，旁边的提示图标说明原因。
- 配置仅保存在当前浏览器的 `workflow_summary_column_settings_v2.mappedColumns` 中，原 v1/v2 单流程设置仍可读取。改名不会改变来源关联；流程或字段临时不可用时保留映射供编辑。恢复默认会清除自定义汇总列及列选择。
- 该配置仅影响汇总表格，既有导出仍使用申请自己的表单结构和数据，不受汇总展示列影响。没有新增接口、数据迁移或申请写入操作。

## 汇总中的详细表单

汇总列表“查看”抽屉中的“详情”使用 `workflow:summary-form-detail:<instanceId>` 入口，继续请求 `/api/v2/dingtalk/h5/workflows/summary/instances/:id`。入口来源编码在页签 key 和链接中，页面刷新及直接链接重新打开时仍保留汇总模式。

普通流程详情继续使用 `workflow:form-detail:<instanceId>` 和普通实例接口。同一条申请从不同入口打开时使用独立页签，避免混用权限。

前端入口只决定请求哪个接口，不授予权限。汇总接口继续由后端检查汇总 API 权限和实例可见范围；不可见记录拒绝访问，前端清除旧表单、显示返回错误，不改用另一个接口重试。详细表单保持只读。

## 计算字段

- 已保存的结果优先展示，遵守配置的小数位数和结果标签映射。
- 历史申请没有保存该计算字段时，按当前所选表单的计算规则，用申请已有的源字段只读补算。
- 历史选择字段若保存的是旧显示标签，而当前选项使用新的数值 value，汇总补算会在标签唯一匹配时转换为当前 value；标签重复或无法匹配时仍显示 `-`，不会任意选择选项。
- 补算结果旁显示“补算”，提示“按当前所选表单规则计算，仅用于汇总展示，不修改历史申请”。
- 只计算同一流程的记录，跨分组引用和明细聚合使用现有公式解析器。
- 引用字段缺失、为空、类型无效、选项计算值无效、公式非法或除数为零时显示 `-`，不把未填写值当作 0。
- 真实的 0 分正常显示；空明细数组的 SUM/COUNT 等沿用现有聚合规则。
- 不修改历史表单版本、不回写申请数据、不更改审批结果。导出仍依据申请所属历史表单及保存数据，不将列表补算值写入导出快照。

例如，“最终分档”公式是 `([field_13] + [field_9]) / 2`，早期申请只保存了两个原始分档。两者均存在时可在汇总中补算，任何一个缺失则保持 `-`；已有最终分档则直接显示已有结果。

## 验证

`cd h5app && pnpm check:workflow-summary-columns` 验证跨分组、历史补算、保存值优先、标签和精度、缺值/非法值、除零、明细、流程隔离、只读计算及普通表单原有计算行为。

本次 `pnpm type-check`、`pnpm build:h5` 和修改文件的 ESLint 通过；本机浏览器实际勾选计算列，验证补算标记、保存结果和缺少输入的显示。全量 lint 仍有既有报错，`check:workflow-module` 仍受既有“发起审批”文案断言影响。

`pnpm check:workflow-summary-form-detail` 验证汇总入口传递、普通旧链接、入口规范化、刷新后接口选择、拒绝时不回退和旧数据清除。后端 `go test ./internal/service/dingtalkh5/workflowsummary ./internal/modules/workflow/transport/httpclient ./internal/support/appapiperm -count=1` 验证汇总范围内的非参与人可读、范围外拒绝及原有路由权限声明。

`pnpm check:workflow-summary-mappings` 覆盖跨流程不同字段 key、各自公式、保存结果/0/false、版本优先级、缺失原因、配置规范化、只读输入、旧设置兼容、保存/替换/恢复默认、历史字段请求去重、权限变化、失败/过期响应，以及列表和定义刷新顺序。
