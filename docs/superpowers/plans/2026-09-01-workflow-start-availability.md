# 工作流流程配置与允许发起时间实施计划

**目标：** 新增“流程配置”页签，将允许发起范围和允许发起时间从发布弹窗迁入设计器，并在运行时统一限制新实例发起。

**架构：** 配置继续存放于开始节点并随草稿和发布版本 JSON 保存。核心包负责结构校验和时间规则计算，应用服务在列表、详情和正式发起链路复用该规则，管理端设计器提供唯一编辑入口。

## 任务 1：核心模型与纯时间规则

- [ ] 为开始节点增加发起时间配置和校验错误码。
- [ ] 增加长期、固定、每周、每月和边界行为测试。
- [ ] 实现按时区计算的纯状态函数。

## 任务 2：发布与运行时

- [ ] 发布时保留草稿中的发起范围和时间配置。
- [ ] 发布定义响应返回时间配置和当前状态。
- [ ] 正式发起在事务内校验实际发布版本。
- [ ] 列表和详情返回当前发起时间状态。

## 任务 3：设计器流程配置页签

- [ ] 新增“流程配置”Tab 和独立组件。
- [ ] 迁移部门、用户发起范围配置。
- [ ] 实现四种发起时间模式的表单交互。
- [ ] 配置错误定位到新页签。

## 任务 4：发布弹窗与契约

- [ ] 发布弹窗只保留流程、版本和配置提示。
- [ ] 发布 API 请求允许空发布配置，兼容旧调用方覆盖发起人配置。
- [ ] 更新前端结构回归检查和架构文档。

## 任务 5：验证

- [ ] 运行核心、发布服务、应用服务和基础设施测试。
- [ ] 运行工作流前端结构检查和生产构建。
- [ ] 在浏览器验证流程配置 Tab、模式切换和发布确认。
