# 应用接口权限 P1/P2 实施计划

## 目标

在统一权限体系中补齐客户端与钉钉 H5 的接口权限，让后台角色和用户覆盖权限都可以配置应用接口访问范围。接口权限继续使用 `permissions` 和 `permission_grants`，不再新增平台专用授权表。

## P1：钉钉 H5 API 权限

1. 新增钉钉 H5 API 权限目录，类型使用 `api_category` 和 `api`。
2. 权限点覆盖工作台、绩效列表、绩效详情、流程操作、人员维护、绩效模版和账号操作。
3. `/api/v2/dingtalk/h5` 已登录路由接入模块内 `ApiPerm` 中间件。
4. 运行时策略：
   - 未初始化统一权限表时保持兼容放行。
   - 用户或角色没有任何钉钉 H5 API allow 授权时保持兼容放行。
   - 一旦配置过钉钉 H5 API allow 授权，则按具体接口权限严格校验。
   - 用户级 deny 始终优先拦截对应接口。

## P2：客户端 API 权限

1. 新增客户端 API 权限目录，类型使用 `api_category` 和 `api`。
2. 权限点覆盖用户资料、收藏、通知、打卡、赛事活动、问卷和考试相关已登录接口。
3. `/api/v2` 客户端已登录路由接入 `ClientPerm` 中间件。
4. 客户端登录 token 新增 `roleId`，旧 token 缺少 `roleId` 时按用户 ID 兼容查询。
5. 运行时策略与钉钉 H5 保持一致：未配置 API allow 时兼容放行，配置后严格校验，用户级 deny 优先。

## 后台配置

1. 角色管理应用权限拆分为：
   - 客户端菜单
   - 钉钉 H5 菜单
   - 客户端接口
   - 钉钉 H5 接口
2. 用户管理的额外授权和禁止权限同步支持上述应用接口权限。
3. 保存仍落到 `permission_grants`，角色使用 `subject_type = role`，用户覆盖使用 `subject_type = user`。

## 验证

1. 新增 `appapiperm` 目录测试，确保客户端与钉钉 H5 API 权限点有类别归属。
2. 新增权限服务结构测试，确保启动同步包含应用 API 权限。
3. 新增角色服务和角色 handler 结构测试，确保 API 权限可回显和保存。
4. 新增路由结构与映射测试，确保客户端和钉钉 H5 已登录路由挂载接口权限中间件。
