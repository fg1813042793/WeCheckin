# 验证脚本收口优化设计

## 背景

项目已经完成了配置环境变量覆盖、启动初始化安全等后端优化，但这些改动目前需要手动记住多条 `go test` 命令来验证。继续优化前，先把当前关键回归检查收口成一条项目级命令，能降低后续迭代遗漏测试的概率。

当前工作区还存在若干未提交实现改动。本轮只新增验证入口和中文文档说明，不修改业务逻辑，避免把收口优化和业务安全改造混在一起。

## 目标

- 新增一个根目录检查脚本，用一条命令运行当前关键后端测试。
- 脚本使用项目内 `.cache/go-build` 作为 Go 构建缓存，避免依赖开发者机器的全局缓存路径。
- 脚本在结束时清理项目内 `.cache`，保持工作区干净。
- README 使用中文说明推荐验证命令和覆盖范围。

## 非目标

- 不升级密码散列算法，不处理 MD5 历史数据迁移。
- 不调整数据库初始化 SQL。
- 不新增前端或管理端测试流程。
- 不改变现有配置加载、启动初始化和业务接口行为。

## 方案

新增 `scripts/check.sh`，作为项目级健康检查入口。脚本从仓库根目录执行以下后端测试：

- `./backend/internal/app/service`
- `./backend/internal/config`
- `./backend/internal/app/formkit/...`

脚本启用 `set -euo pipefail`，任何测试失败都会立即返回非零退出码。脚本会自动定位仓库根目录，方便开发者从任意目录调用。

README 增加“验证项目健康状态”说明，推荐使用 `bash scripts/check.sh`。说明中明确这条命令覆盖当前后端关键回归测试，后续如果新增稳定测试套件，可以继续扩展脚本。

## 测试与验收

- 执行 `bash scripts/check.sh` 应通过。
- 脚本运行后不应留下 `.cache` 目录。
- README 中应能看到中文验证说明。
- `git status --short` 中除了本轮新增脚本和 README 改动外，不应出现由脚本运行产生的缓存文件。

## 风险

这轮改动不触碰业务逻辑，主要风险是脚本路径或缓存清理不符合不同 shell 环境。使用 `bash` 执行脚本，并用脚本自身位置定位仓库根目录，可以把该风险控制在较低范围。
