# 流程发起人用户名展示设计

## 目标

流程审批中所有标记为“发起人”的用户可见位置展示用户名，不再展示用户 ID。`starterId` 继续保留在接口中，仅用于权限判断、数据过滤和撤回校验。

## 接口契约

- 在流程实例摘要 `InstanceSummary` 中新增 `starterName`。
- 流程实例列表和详情沿用同一摘要结构，因此同时返回 `starterId` 与 `starterName`。
- `starterName` 优先取 `users.user_name`，为空时取 `users.user_account`。
- 用户不存在或名称与账号均为空时，接口返回空字符串，客户端展示“未知用户”，不回退显示 ID。

## 查询与映射

- 列表查询收集当前页的发起人 ID，一次性查询对应用户，避免逐条查询。
- 详情查询只解析当前实例的发起人姓名。
- 现有通知模板的姓名回退行为保持不变，不修改通知发送逻辑。

## H5 展示

- `WorkflowInstanceSummary` 增加 `starterName` 类型字段。
- 流程详情摘要中的“发起人”显示 `starterName`，空值显示“未知用户”。
- 不修改处理人、历史操作人等非“发起人”字段的展示。

## 验证

- 后端测试覆盖姓名优先级、账号回退、未知用户空值，以及列表批量映射。
- HTTP 契约测试确认详情响应包含 `starterName`。
- H5 工作流结构检查禁止“发起人”继续绑定 `starterId`。
- 运行后端相关包测试、H5 结构检查、类型检查、目标 lint 和 H5 构建。
