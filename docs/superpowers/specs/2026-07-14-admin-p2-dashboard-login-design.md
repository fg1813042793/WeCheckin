# Admin P2 控制台和登录体验优化设计

## 背景

上一轮 P1 已经完成后台壳层、通用列表样式和用户管理操作列收敛。本轮继续处理 P2 中投入产出较高的界面问题：控制台信息层级太薄，登录页缺少产品识别和辅助信息，历史默认菜单兜底中的考试入口不完整。

> 当前状态：默认全量菜单兜底已被统一权限菜单替代，后台侧栏只展示 `/api/v2/admin/me/menus` 返回的授权菜单。本文中涉及默认菜单兜底的内容仅作为历史记录。

## 目标

1. 控制台从简单数字卡片升级为可扫读的运营概览：核心指标、待办入口、快捷入口、模块健康状态。
2. 登录页视觉更像正式后台入口：品牌区、能力摘要、账号密码图标、移动端适配。
3. 历史默认菜单兜底曾补全考试记录、考试统计和考试表单相关入口；当前已废弃该兜底机制。
4. 新增静态检查，防止控制台、登录页和导航配置回退到旧状态。

## 非目标

- 不改变 `adminApi.home()` 返回结构。
- 不引入图表库新用法，不增加新的运行依赖。
- 不拆分问卷/考试设计器大文件。
- 不改变登录接口、权限接口和 token 存储逻辑。

## 方案

### 控制台

`admin/src/views/dashboard/index.vue` 使用已有 `admin-page` 和 `admin-card` 样式。接口仍然只读 `adminApi.home()`，将现有统计字段整理为：

- 顶部欢迎区：说明当前后台定位，提供用户管理、问卷管理、考试管理、系统配置快捷入口。
- 核心指标网格：用户数、打卡项目、内容、管理员、赛事活动、参与人次。
- 待办和状态区域：待审核用户、内容发布、活动管理、系统配置等入口，用静态文案和路由跳转承载，不依赖新接口。
- 失败兜底：接口失败时指标保留 `-`，页面仍完整渲染。

### 登录页

`admin/src/views/login/index.vue` 保留现有表单逻辑，新增双栏登录布局：

- 左侧品牌区：项目名、管理能力摘要、运行提示。
- 右侧登录卡片：账号/密码图标输入，登录按钮，轻量提示。
- 小屏下自动变为单栏，隐藏大面积品牌介绍，减少溢出风险。

### 历史默认菜单兜底

早期方案曾在 `admin/src/router/adminRoutes.ts` 中维护默认菜单兜底，在线考试分组补充：

- 考试管理
- 考试记录
- 考试统计
- 考试表单设计器
- 考试答题报表

## 验证

- 新增 `admin/scripts/check-p2-ui.mjs`。
- 接入 `admin/package.json` 和根级 `scripts/check.sh`。
- 运行 `npm --prefix admin run check:p2-ui`、`bash scripts/check.sh`、`CHECK_ADMIN_BUILD=1 bash scripts/check.sh`。
