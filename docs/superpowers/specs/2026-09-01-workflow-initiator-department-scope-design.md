# 工作流发布发起部门范围设计

## 1. 目标

扩展通用工作流的发布发起范围，使管理员在发布流程时可以同时选择多个部门和多个指定用户。满足任一选中部门或任一指定用户条件的人员均可发起流程。

本功能只修改独立通用工作流模块，不修改现有绩效业务流程。

## 2. 范围语义

发布范围继续使用两种模式：

- `all`：全部有效用户均可发起。
- `specified`：指定范围内的用户可发起。

`specified` 的允许范围由两部分组成：

- `userIds`：明确允许的用户。
- `departmentIds`：允许发起的部门。

两类范围按并集判断。用户被明确选中，或用户当前所属任一部门位于 `departmentIds` 中，即允许发起。

部门匹配只包含管理员明确选择的部门本身，不自动包含其子部门。用户支持多部门归属，任一所属部门命中即可。

## 3. 数据模型

开始节点的发起人配置扩展为：

```json
{
  "scope": "specified",
  "userIds": [12, 18],
  "departmentIds": [3, 7]
}
```

后端 `InitiatorConfig` 增加 `DepartmentIDs []uint`，JSON 字段名为 `departmentIds`；前端 `WorkflowInitiatorConfig` 增加 `departmentIds?: number[]`。

约束如下：

- `all` 模式下 `userIds` 和 `departmentIds` 都必须为空。
- `specified` 模式下两类 ID 至少有一类非空。
- 所有 ID 必须为正整数，同一列表内不能重复。
- 规则结构校验不额外查询组织表，保持与现有指定用户校验一致；已删除的用户或部门自然无法命中。

这是兼容性 JSON 扩展，不提升流程定义 Schema 版本。历史发布版本没有 `departmentIds` 时仍按原指定用户规则执行。

## 4. 流程配置交互

发起范围已迁入流程设计器的“流程配置”页签，使用“全部用户”和“指定范围”两种模式。

选择“指定范围”后显示：

- “允许发起部门”：使用 Element Plus 多选部门树，开启 `check-strictly`，父子节点互不级联；支持折叠标签和清空。
- “额外允许用户”：复用现有 `WorkflowUserTreePicker`，允许在部门范围外补充具体人员，也允许只配置用户。

保存和发布前将两类 ID 分别去重、转为正整数。当两类都为空时校验失败并提示“请选择允许发起的部门或用户”。

再次打开流程时从开始节点当前配置回显部门和用户。选择“全部用户”时保存 `scope: all`，不携带部门或用户 ID。发布弹窗只确认版本，不再提供重复编辑入口。

## 5. 运行时鉴权

部门范围使用发起时的实时组织关系，而不是发布时把部门展开为固定用户列表。

统一判断流程为：

1. `scope != specified` 时允许有效用户发起。
2. 发起用户 ID 位于 `userIds` 时允许。
3. 查询该用户当前全部 `user_depts` 关系。
4. 任一用户部门位于 `departmentIds` 时允许。
5. 均未命中时拒绝。

以下入口复用同一判断语义：

- 客户端可发起流程列表。
- 客户端流程定义详情。
- 客户端正式发起流程。
- 管理员针对指定业务用户发起流程。

管理员查询全部已发布流程时不按管理员本人过滤，但代发动作必须按被代发用户执行范围校验。

## 6. 后端边界

应用层增加用户部门读取能力，基础设施通过 `user_depts` 一次查询用户全部部门 ID。列表接口每次请求只查询一次用户部门，再对所有定义执行内存判断，避免按流程逐条查询。

正式发起在事务内读取目标发起人的部门关系，并对具体发布版本再次校验，防止绕过列表或详情接口直接提交。

发布服务复制开始节点发起配置时，对 `UserIDs` 和 `DepartmentIDs` 都做防御性复制。发布版本映射返回完整配置，确保前端回显与历史版本审计一致。

## 7. 错误处理

- 指定范围为空：发布前端提示“请选择允许发起的部门或用户”，后端返回 `initiator_invalid`。
- ID 为零或列表内重复：后端返回 `initiator_invalid`。
- 用户不在指定用户或部门范围：继续返回“该用户不在流程允许的发起人范围内”。
- 用户部门查询失败：返回存储错误，不降级为允许发起。
- 用户没有部门且未被明确指定：拒绝发起。

## 8. 测试范围

### 8.1 后端

- 定义校验接受只选用户、只选部门、用户和部门并集。
- 定义校验拒绝空指定范围、零 ID、重复部门 ID 以及 `all` 携带部门 ID。
- 发布服务正确保留和防御性复制部门 ID。
- 发起范围判断覆盖明确用户命中、任一部门命中、多部门未命中和无部门用户。
- 客户端列表与详情按部门过滤。
- 正式发起和管理员代发不能绕过部门范围。
- Gorm 存储一次读取用户全部 `user_depts`。

### 8.2 前端

- 流程配置页签回显和保存多个部门 ID。
- 部门选择不级联子部门。
- 部门或用户任一非空即可发布，两者都为空时阻止发布。
- “全部用户”提交时清除范围 ID。
- 工作流发布与运行页面结构回归检查通过。

## 9. 非目标

- 不支持自动包含子部门。
- 不在发布时把部门成员展开并固化为用户 ID。
- 不新增工作流发起范围关系表。
- 不增加角色、岗位或组织审批身份作为发起范围。
