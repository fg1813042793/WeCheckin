# 明细列表列合计校验规则设计

## 1. 目标

为通用工作流表单的明细列表增加专用“列合计”校验规则。管理员可以选择明细中的数字或金额列，对所有明细行的该列求和，并将合计值与配置目标值进行比较。

本功能只扩展独立通用工作流模块，不修改现有绩效业务流程。

## 2. 规则模型

新增规则类型 `column_sum`，沿用现有结构化校验规则模型，并增加以下参数：

- `column`：参与合计的明细列编码。
- `operator`：比较关系，支持 `eq`、`ne`、`gt`、`gte`、`lt`、`lte`。
- `value`：比较目标值。
- `message`：可选的自定义错误提示。

规则只能配置在 `detail_list` 字段上，`column` 只能引用该明细列表中的 `number` 或 `amount` 列。

## 3. 计算语义

- 遍历明细列表全部行，对指定列求和。
- 空单元格按 `0` 参与合计。
- 如果明细列配置为必填，空单元格优先触发列必填校验，不进入最终合计判断。
- 非数字值继续由明细列类型校验拒绝。
- 空明细列表的合计值为 `0`；是否允许空列表仍由明细列表的 `minRows` 控制。
- 金额和数字统一按现有数值解析方式计算，比较结果不改变原始表单数据。

## 4. 设计器交互

- 明细列表字段的“高级规则”中增加“列合计”。
- 选择该规则后显示“合计列”“比较关系”“目标值”和“错误提示”。
- “合计列”只展示当前明细列表中的数字和金额列。
- 当不存在可合计列时，不展示“列合计”规则类型。
- 明细列表不再展示普通“字段比较”规则。
- 普通标量字段新增“字段比较”规则时，目标字段保持未选择状态，要求管理员明确选择。

## 5. 校验边界

### 5.1 发布校验

发布前检查：

- 规则只能属于明细列表。
- 引用列存在且类型为数字或金额。
- 比较关系有效。
- 目标值存在且为有效数字。

任何一项不符合时返回 `form_field_rules_invalid`，阻止发布。

### 5.2 运行时校验

- 管理端发起流程和处理任务前执行前端校验并显示明细列表字段错误。
- 后端在发起实例时执行权威校验。
- 审批节点修改表单时，后端先合并当前表单与补丁，再执行列合计校验。
- 规则随流程发布版本保存，旧流程实例继续使用其发起时版本中的规则。

## 6. 错误提示

配置了 `message` 时原样使用自定义提示；未配置时生成默认提示，例如：

`本月目标“权重”列合计必须等于100`

## 7. 测试范围

- 后端验证六种比较关系、空值按零、必填优先和无效列引用。
- 前端验证列合计计算、默认错误提示和自定义错误提示。
- 结构检查验证明细列表接入“列合计”，且不再出现普通“字段比较”。
- 运行工作流模块测试、管理端回归检查、TypeScript 检查和生产构建。
