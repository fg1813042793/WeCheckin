# H5App 流程汇总跨版本批量导出设计

## 目标

H5App 流程汇总允许将当前页任意已选流程实例批量导出，不再要求记录属于同一个流程定义。不同流程、不同发布版本可以进入同一个导出任务，同时保持每条历史实例使用其绑定版本的表单结构。

## 根因

当前 H5App 在导出前要求所有记录的 `definitionId` 相同，并将该 ID 作为导出接口参数。后端 `Export` 同样要求 `definitionId` 非零，再用它过滤已选实例。历史数据中即使流程名称相同，也可能存在不同定义 ID，因此前端会提示“请选择同一流程的记录批量导出”。

实际导出渲染已经按实例工作：服务逐条读取实例详情，详情加载使用实例保存的 `definitionId + definitionVersion`，Excel 为每条实例生成独立 Sheet，PDF 和 DOCX 多条导出时分别生成文件并打包。因此渲染层不需要统一定义或版本。

## 接口调整

`GET /api/v2/dingtalk/h5/workflows/summary/export` 仅接收：

- `instanceIds`：需要导出的实例 ID，最多 50 条。
- `format`：`xlsx`、`pdf` 或 `docx`。
- `token`：H5 下载场景使用的登录 token。

移除 `definitionId` 导出参数。列表与详情接口的定义筛选行为不变。

## 后端行为

- `ExportRequest` 不再包含 `DefinitionID`。
- 导出不再执行流程定义必填校验。
- 授权查询以实例 ID 列表和当前用户的数据可见范围为边界，不附加定义 ID 条件。
- 授权查询返回数量必须与去重后的实例 ID 数量一致，否则整体拒绝导出。
- 每条授权实例继续单独调用详情加载，自动读取实例绑定的历史定义版本和表单结构。
- Excel 保持一条流程实例一个 Sheet；不同表单结构互不合并。
- PDF、DOCX 多条导出保持 ZIP 打包行为。

## H5App 行为

- 删除按 `definitionId` 分组和“请选择同一流程”的提示。
- 批量导出只校验权限、非空选择和现有格式。
- `workflowSummaryExportUrl` 只接收实例 ID 与格式。
- 单条导出和批量导出共用相同调用路径。

## 兼容与安全

- 不修改汇总列表筛选、列设置、详情查看和单条选择行为。
- 不使用当前最新发布版本覆盖历史实例。
- 不降低数据权限；跨定义导出仍必须通过现有 `InstanceVisibility` 授权查询。
- 不允许部分成功：任一实例不可见时，整个导出请求失败。
- 最大导出数量和文件大小限制保持不变。

## 测试

- 后端服务测试覆盖不同 `definitionId`、不同 `definitionVersion` 的实例能够在同一次导出中通过授权并加载详情。
- 后端处理器测试覆盖导出请求不再要求或传递 `definitionId`。
- 保留不可见实例导致整体拒绝的回归测试。
- H5 静态契约检查要求导出 URL 不含 `definitionId`，并禁止恢复“同一流程”前端限制。
- 运行工作流汇总、H5 类型检查、Lint、工作流模块检查与 H5 构建。
