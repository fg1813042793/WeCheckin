# 定时发送流程开始通知设计

## 目标

定时任务新增“发送流程开始通知”注册任务。管理员只选择一个启用且跳转目标为“发起指定流程”的发送模板，不再手工选择收件用户。任务执行时按照模板绑定流程当前发布的发起范围动态计算收件人。

## 配置

注册键：`notification.workflow_start.send`。

参数仅包含：

```json
{ "templateId": 7 }
```

模板候选只返回 `enabled=true` 且 `target_kind=workflow_start` 的模板。定时任务保存模板 ID，不保存用户、部门、模板版本、标题或正文。

## 执行流程

1. 读取模板当前版本并校验模板启用、目标类型为流程发起、目标流程仍已发布。
2. 读取目标流程当前发起配置。
3. 全部用户范围：解析当前全部启用用户，再剔除排除用户。
4. 指定范围：解析当前指定启用用户，以及指定部门及其子部门中的启用用户，合并去重后剔除排除用户。
5. 使用模板当前默认标题、正文、消息类型和流程跳转目标发送钉钉通知。
6. 使用定时任务运行 ID 作为发送来源，保留现有重试与计数日志语义。

任务每次运行重新读取模板、流程范围和组织数据，因此模板内容、流程发布对象、用户状态和部门成员变化均在下次执行生效。

## 失败语义

- 模板不存在、停用、不是流程目标，或目标流程取消发布：配置不可用，本次运行失败，不回退首页。
- 当前范围没有启用用户：`no_recipients`，不发送。
- 数据库或钉钉临时错误：保留可重试错误。
- 日志只记录计划、成功、跳过和失败数量，不记录正文和完整用户列表。

## 权限

创建和编辑该任务需要定时任务管理权限以及现有 `notification:dingtalk:send` 权限，不额外要求模板编辑权限。任务执行仍由 taskd 完成。

## 兼容性

现有 `notification.dingtalk.send` 保持不变。现有发送模板、手工发送、站内信和工作流实例自动通知不受影响。
