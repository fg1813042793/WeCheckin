# Admin P1 界面优化设计

## 背景

WeCheckin 管理后台已经覆盖控制台、用户、问卷、考试、配置等核心功能，但当前界面仍有几个会影响日常管理效率的问题：整体布局较基础，页面标题、面包屑、菜单状态和内容区域缺少统一结构；列表页筛选、工具栏和分页样式不一致；用户管理操作列按钮过多，固定宽度过大，挤占表格主体信息。

本批次只做 P1 界面体验优化，目标是提升后台管理的基础可用性和一致性，不改动后端接口和核心业务流程。

## 目标

1. 后台整体壳层更像生产可用的管理后台：支持侧栏折叠、面包屑、清晰的页面标题、菜单加载/失败/空状态。
2. 建立轻量全局后台样式，统一页面容器、工具栏、表格操作区和分页区。
3. 优化用户管理列表，把大量行内按钮收敛为“主操作 + 更多菜单”，降低操作列宽度。
4. 增加静态检查，防止后续回退到无折叠侧栏、无面包屑、大操作列等旧形态。

## 非目标

- 不重构 3000 行级别的问卷/考试设计器。
- 不引入新的 UI 框架。
- 不改变权限、登录、接口参数和后端数据结构。
- 不做营销页式视觉重绘，后台仍保持信息密度和管理效率优先。

## 设计方案

### 后台壳层

`admin/src/views/layout/index.vue` 保留现有动态菜单和 fallback 菜单机制，在此基础上增加：

- `sidebarCollapsed` 状态和折叠按钮。
- Element Plus `el-breadcrumb`，根据当前路由标题和菜单树推导当前位置。
- 顶部右侧保留管理员头像和退出登录。
- 菜单加载、加载失败、空菜单三个状态提示。
- 主内容区使用统一 `.admin-main` 容器，避免每个页面重复写背景和间距。

### 全局后台样式

新增 `admin/src/styles/admin.css`，在 `admin/src/main.ts` 中导入。提供以下轻量类：

- `.admin-page`
- `.admin-card`
- `.admin-toolbar`
- `.admin-toolbar__left`
- `.admin-toolbar__right`
- `.admin-table-actions`
- `.admin-pagination`

这些类只服务后台管理页面，不影响前端小程序项目。

### 用户管理列表

`admin/src/views/user/index.vue` 调整为：

- 根容器使用 `.admin-page`。
- 卡片使用 `.admin-card`。
- 筛选栏和工具栏使用 `.admin-toolbar` 结构。
- 操作列从 `500` 收敛到约 `220`。
- 保留“详情/编辑”作为高频按钮，其余“审核通过/禁用/恢复正常/重置密码/删除”进入更多菜单或确认弹层。
- 去掉“导入功能开发中”的假入口，减少无效操作。

## 错误和边界

- 菜单接口失败时继续使用 fallback 菜单，并显示轻量提示，不阻断后台使用。
- 权限加载失败时仍进入页面，但保留现有权限工具的默认行为。
- 删除、重置密码等危险操作继续使用确认弹层。

## 验证

- 新增 `admin/scripts/check-ui-shell.mjs` 检查后台壳层能力。
- 新增 `admin/scripts/check-user-list-ui.mjs` 检查用户管理列表结构。
- 将两个检查接入 `admin/package.json` 和根级 `scripts/check.sh`。
- 运行 `bash scripts/check.sh` 和 `CHECK_ADMIN_BUILD=1 bash scripts/check.sh`。
