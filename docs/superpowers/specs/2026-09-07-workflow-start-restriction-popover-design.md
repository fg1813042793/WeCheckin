# 流程发起限制悬浮提示设计

## 目标

在 H5App 的“发起审批”流程卡片上，为 PC 用户提供限制条件悬浮提示，帮助用户在进入表单前判断流程当前是否可发起。手机端保持现有卡片点击行为，不新增弹层或信息图标。

## 交互设计

- PC 端鼠标悬停或键盘聚焦流程卡片时，在卡片附近显示轻量浮层。
- 浮层不改变卡片尺寸，不引起流程列表重排。
- 卡片点击仍进入流程发起页；不可发起时阻止进入，并提示接口返回状态对应的具体原因。
- 手机端不渲染限制浮层，卡片布局和点击行为保持现状。

## 展示内容

浮层按当前流程配置和当前用户状态展示：

1. 当前状态：可发起、尚未开放、当前不在开放时段、已过期或当前周期次数已用完。
2. 开放时间：长期有效、指定时间、每周开放、每月开放或跨月开放窗口。
3. 发起次数：不限次数，或本周期已使用次数和剩余次数。
4. 发起范围：仅显示“当前账号可发起”，不展示指定用户或部门名单。
5. 重置时间：存在周期重置时间时显示；永久总次数限制不显示重置时间。

没有配置时间或次数限制时，分别显示“长期有效”和“不限次数”，避免空白信息产生歧义。

## 数据边界

- 复用流程定义列表中的 `availability`、`availabilityStatus`、`startLimit` 和 `startLimitStatus`。
- 不新增接口，不在悬停时发起请求。
- 后端仍是发起资格、开放时间和次数限制的最终校验边界。
- 前端只负责格式化已返回规则和状态，不自行计算剩余次数。

## 代码结构

- 在工作流模块内新增纯函数，负责把流程限制配置转换为稳定的展示模型。
- `WorkflowCenter.vue` 只负责浮层显隐、定位和卡片交互，避免在模板中堆叠规则判断。
- 使用 H5 条件编译和支持悬停的媒体查询限定 PC 行为，不影响其他 uni-app 平台。

## 验证

- 纯函数测试覆盖长期有效、固定时间、周期开放、次数限制、次数耗尽和重置时间。
- H5App 契约检查确认卡片存在可聚焦入口和限制浮层结构。
- 运行 `pnpm lint`、`pnpm type-check`、`pnpm check:workflow-module`、`pnpm check:ui-style` 和 `pnpm build:h5`。
- 手动检查标准 PC 与窄屏 PC；手机尺寸确认不出现限制浮层且卡片布局不变。
