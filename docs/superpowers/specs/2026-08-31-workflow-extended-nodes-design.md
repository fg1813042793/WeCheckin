# 通用工作流扩展节点设计

## 1. 目标与边界

在现有独立 Go 工作流模块和管理端流程设计器中补齐四类可插入节点，并增加管理员按指定用户独立发起流程的配置能力。此次改动只扩展通用 workflow 模块，不修改现有绩效业务流程。

本次新增能力：

- 办理/填写节点 `handle`。
- 抄送/通知节点 `cc`。
- 自动动作节点 `automation`。
- 定时/等待节点 `timer`。
- 按指定用户发起：属于发起配置能力，不作为流程图节点。

## 2. 节点语义

### 2.1 办理/填写节点

办理节点解析一个处理人并创建人工任务。处理人可以填写当前节点具有写权限的流程表单字段，然后执行“提交”。办理任务不提供“驳回”动作，提交后任务状态变为 `completed`，流程继续。

首版仅支持单人办理。多人协作、抢办和退回留给后续版本，避免把办理节点重新做成审批节点。

### 2.2 抄送/通知节点

抄送节点复用现有人员解析器。节点到达后为每个接收人写入 `node_cc` 历史事件并立即继续，不创建阻塞任务。历史事件是通知订阅器的稳定扩展点，本次不直接依赖钉钉、短信或邮件实现。

### 2.3 自动动作节点

自动动作节点首版只支持 `set_variables`：把配置中的键值合并到流程变量后写入 `node_automated` 历史事件并立即继续。业务回写、HTTP 回调和脚本执行需要独立的重试、鉴权及幂等设计，不进入本次范围。

### 2.4 定时/等待节点

定时节点配置等待秒数 `delaySeconds`。令牌首次进入时计算到期时间，写入实例保留变量并转为 `waiting`。管理员调用“推进到期节点”接口时，引擎只恢复已经到期的定时令牌；重复调用没有副作用。

项目当前没有通用后台调度器，因此首版由管理端实例详情提供显式推进动作。领域层和应用层保留独立的到期恢复入口，后续接入统一调度器时不需要改变流程定义或令牌语义。

## 3. 按指定用户发起

发起对话框增加“普通发起”和“按用户分别发起”两种模式。按用户分别发起时可以选择一个或多个用户，管理端为每个用户调用一次现有启动接口：

- 每个用户得到独立流程实例。
- 变量自动增加 `targetUserId`。
- 业务标识使用 `<基础业务标识>:user:<用户ID>`，满足现有定义、业务类型、业务标识唯一约束。
- 其他流程变量和表单初始数据复制到每个实例。
- 单个实例失败不回滚已经成功创建的其他实例，界面展示成功数和失败用户。

流程设计者可以把办理或审批节点的处理人来源配置为流程变量 `targetUserId`，从而把每个独立实例派给对应用户。

## 4. 定义与 BPMN

流程定义 JSON 为新增节点增加以下配置：

- `handle`、`cc`：复用 `assignee`。
- `handle`：复用 `formPermissions`。
- `automation`：`automation.type` 和 `automation.variables`。
- `timer`：`timer.delaySeconds`。

BPMN 导出使用 `userTask` 表示办理节点、`serviceTask` 表示抄送和自动动作、带 `timeDuration` 的 `intermediateCatchEvent` 表示定时节点。Go 引擎仍以发布版本 JSON 为唯一运行依据。

## 5. 校验与错误处理

- 办理和抄送节点必须配置有效处理人来源。
- 自动动作类型必须为 `set_variables`，变量集合不能为空，变量名必须有效。
- 定时等待秒数范围为 1 至 31536000。
- 办理任务只接受 `submit`；审批任务只接受 `approve` 或 `reject`。
- 到期恢复仅处理运行中实例的定时等待令牌；未到期时返回推进数量 0。
- 自动动作、抄送或人员解析失败时，启动或任务完成事务整体失败，不保存半成品状态。

## 6. 测试范围

- 定义校验覆盖四类节点的有效与无效配置。
- BPMN 测试覆盖四类节点的元素映射。
- 领域引擎覆盖办理提交、抄送自动通过、变量写入、定时等待和幂等恢复。
- 应用服务和管理端 HTTP 覆盖定时恢复事务与认证身份。
- 管理端静态回归检查覆盖节点菜单、配置面板、办理动作和按用户独立发起。
- 最终运行 Go 定向测试、管理端工作流检查和完整管理端构建。
