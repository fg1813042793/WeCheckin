# Admin 用户列表组合筛选设计

## 目标

在管理后台用户管理页增加状态、手机号、岗位、直属上级和角色筛选，并保持现有用户名关键词、排序、分页、数据范围和导出行为不被破坏。

## 交互设计

- 用户名/姓名：文本输入，沿用现有 `keyword` 查询。
- 手机号：独立文本输入，后端使用包含匹配。
- 状态：下拉精确筛选，支持全部、待审核、正常、已禁用、管理员。
- 岗位：可搜索下拉，值为岗位 ID。
- 直属上级：可搜索下拉，值为用户 ID。
- 角色：可搜索下拉，值为角色 ID。
- 搜索条件在宽屏单行展示，空间不足时自动换行；提供搜索和重置按钮。
- 搜索或重置后回到第一页，分页和排序继续携带当前筛选条件。

## 前端边界

新增 `UserListFilters.vue` 承担筛选控件和布局，避免继续增加已超复杂度预算的 `user/index.vue`。页面只保留筛选状态、选项加载、请求参数组装和搜索/重置编排。

新增 `AdminUserListQuery` 类型并用于 `adminApi.userList`，防止筛选参数继续以无类型对象扩散。

## 后端边界

新增 `UserListFilter`：

- `Keyword string`
- `Mobile string`
- `Status *int`
- `PositionID uint`
- `ManagerUserID uint`
- `RoleID uint`

基础字段直接过滤 `users` 表。直属上级通过当前有效的 `user_reporting_relations` 直属关系 `EXISTS` 查询。角色在 `user_roles` 可用时同时匹配多角色关系和历史 `users.user_role_id`，否则只匹配历史主角色字段。

任一筛选条件存在时禁用无条件总数缓存，确保分页总数与筛选结果一致。所有条件继续叠加管理员数据范围限制。

## 接口契约

`GET /api/v2/admin/users` 新增可选查询参数：

- `mobile`
- `status`
- `positionId`
- `managerUserId`
- `roleId`

接口路径、响应结构和权限编码不变。同步更新 Swagger 源声明和生成文档。

## 错误处理

- 非法状态值或非法 ID 参数返回明确的参数错误，不进入查询。
- 选项加载失败时保留基础关键词和手机号搜索，相关下拉显示为空。
- 列表请求失败沿用现有请求层提示并清空当前列表。

## 验证

- 后端 DryRun 测试覆盖五类筛选 SQL、角色兼容和无筛选缓存判定。
- Handler 结构测试覆盖查询参数解析与服务调用。
- Admin 契约检查覆盖筛选组件、参数传递、搜索和重置。
- 浏览器验证单条件、组合条件、重置、分页和窄屏换行。
