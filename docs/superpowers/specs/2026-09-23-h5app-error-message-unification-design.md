# H5App 错误提示统一设计

## 目标

统一 H5App 页面错误提示，使错误对象中存在具体业务信息时优先展示具体内容，只有无法提取具体内容时才使用页面传入的兜底文案。

本期范围为 `h5app/src/`，不改旧 `frontend/` 客户端、不改后端错误协议、不改变登录过期处理和请求拦截器的职责。

## 错误信息优先级

公共工具 `src/common/app-error.ts` 按以下顺序提取第一条非空文本：

1. `error.msg`
2. `error.message`
3. `error.data.msg` / `error.data.message`
4. `error.response.data.msg` / `error.response.data.message`
5. `error.errMsg`
6. 调用方传入的 fallback

工具只返回面向用户的短文本，不展示堆栈、SQL、本地路径、请求体和 token。

## 展示规则

- 页面 `catch` 有错误对象时调用 `showAppError(error, fallback)`。
- 字段级表单校验继续由表单组件直接显示具体错误；提交前 toast 使用第一条具体错误。
- 请求拦截器已经显示的业务错误不再由页面重复弹出。
- 文件选择、剪贴板、设备权限等没有后端错误对象的回调保留场景化提示，例如“当前设备无法打开此附件”。
- 列表错误状态使用解析后的具体文本，无法解析时显示页面场景 fallback。

## 改造范围

优先覆盖：

- 工作流中心、详情、发起、修订、汇总和附件操作。
- 绩效页面的加载/提交失败。
- 反馈、站内信和通知面板的加载/删除/已读失败。
- App 壳和用户资料保存/头像上传。
- H5 API 上传错误解析。

纯本地校验、权限提示、用户主动操作缺失提示不强行改成错误解析工具。

## 验证

- 公共工具单元式脚本覆盖嵌套响应、Error、空错误和敏感内容过滤。
- 结构检查扫描重点页面不得继续使用可替换的固定 catch 失败文案。
- 运行 `pnpm lint`、`pnpm type-check`、`pnpm build:h5` 和公共错误检查。
