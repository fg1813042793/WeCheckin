# 通用流程全节点进度设计

## 背景与目标

当前钉钉 H5 的“流程流转记录”只遍历流程实例已经生成的任务，因此开始、结束、条件/并行网关、抄送、通知、自动动作、定时等待，以及尚未生成任务的审批或办理节点不会显示。

本次改造目标是让实例详情展示该实例对应流程版本的全部节点，并由后端统一返回节点进度。改造仅作用于独立通用工作流模块，不修改现有绩效业务流程。

## 方案选择

采用“后端统一计算节点进度，前端按契约展示”的方案：

- 后端从实例记录的 `definitionId + definitionVersion` 加载历史发布版本，不能使用流程当前最新版。
- 后端结合流程图、任务、令牌和历史事件计算节点进度。
- 钉钉 H5 展示后端返回的完整节点进度和节点下任务明细。
- Admin、Frontend 后续可以直接复用同一详情契约，不需要各端重新实现进度判断。

不采用由 H5 使用当前发布定义补齐节点的方案，因为流程定义升级后会破坏历史实例展示。

## 接口契约

在现有 `InstanceDetail` 中增加向后兼容字段 `nodeProgress`，不修改路由、权限和数据库结构。

每个节点进度项包含：

- `nodeId`：发布版本内节点 ID。
- `nodeName`：发布时节点名称。
- `nodeType`：开始、审批、办理、网关、抄送、通知、自动动作、定时或结束等节点类型。
- `gatewayMode`：网关的分支/汇聚模式，非网关为空。
- `status`：稳定的节点进度状态。

状态值和展示语义为：

| 状态值 | 展示文案 | 语义 |
| --- | --- | --- |
| `completed` | 已完成 | 节点已执行完成 |
| `processing` | 处理中 | 节点存在待处理/待激活任务，或令牌正在该节点活动/等待 |
| `not_started` | 未开始 | 流程仍在运行，但尚未到达该节点 |
| `skipped` | 已跳过 | 流程正常完成后，该节点所在路径未被选择 |
| `terminated` | 已终止 | 流程驳回、撤回或取消后，该节点未继续执行，或节点导致流程终止 |

`nodeProgress` 按流程拓扑顺序返回；同一拓扑层级按设计器坐标从左到右排序，坐标缺失时保持发布定义顺序。

## 进度计算

进度计算放在工作流 application 层的可测试纯投影函数中，输入发布定义和实例详情数据，不依赖 GORM、HTTP 或页面状态，也不修改 domain 状态机。

计算证据包括：

- 开始节点和实例开始时间。
- 节点下全部任务及其状态。
- 当前令牌的节点和状态。
- 带 `nodeId` 的流程历史事件。
- 实例终态和结束时间。
- 发布版本中的节点、连线和网关结构。

状态优先级如下：

1. 节点存在 `pending`/`waiting` 任务，或存在 `active`/`waiting` 令牌时为 `processing`。
2. 节点存在拒绝任务，或流程在该节点终止时为 `terminated`。
3. 开始节点、成功结束节点、已成功处理任务节点、已触发的抄送/通知/自动动作、已恢复的定时节点为 `completed`。
4. 条件/并行网关不直接生成任务，使用图可达关系和已执行后继节点推导是否已经通过。只有位于从开始节点到已执行节点的必经路径上的网关才标记为 `completed`，避免把未选条件分支算作已执行。
5. 无执行证据的节点在运行实例中为 `not_started`；正常完成实例中为 `skipped`；驳回、撤回或取消实例中为 `terminated`。

旧实例没有通用的“进入节点/完成节点”事件时，仍使用已有任务、令牌、节点事件和图结构推导，不要求数据迁移。推导不能证明经过的未选路径保持 `skipped` 或 `terminated`，不伪造处理人和处理时间。

## H5 展示

“流程流转记录”区域改为全节点纵向进度列表：

- 每个节点显示节点名称、节点类型和五态标签。
- 使用颜色和连接线区分已完成、处理中、未开始、已跳过和已终止。
- 审批/办理节点下归并展示该节点的全部任务，保留处理人、处理时间、动作和意见。
- 开始节点显示发起人和发起时间；结束节点完成时显示结束时间。
- 网关、抄送、通知、自动动作和定时节点没有人工任务时只显示节点进度，不制造处理人信息。
- 原始流程事件继续保留在节点进度列表下方，用于查看详细流转时间线。
- 历史抽屉和办理详情的“流程流转记录”页使用同一进度组件，避免两处展示语义分叉。

## 兼容与错误处理

- `nodeProgress` 是新增响应字段，旧调用端忽略即可。
- H5 在后端暂未返回该字段时回退到现有任务列表，避免灰度发布期间详情空白。
- 流程版本记录不存在或损坏时维持现有详情接口错误处理，不使用当前定义兜底。
- 本次不新增数据库迁移、不修改权限 key、不修改工作流执行状态。

## 测试与验证

后端测试覆盖：

- 线性流程的已完成、处理中和未开始节点。
- 条件分支正常完成后的已完成路径和已跳过路径。
- 并行分支中同时处理、部分完成和汇聚后的状态。
- 驳回、撤回、取消后的已终止节点。
- 详情严格使用实例绑定版本，并返回全部节点。
- 旧实例缺少通用节点事件时的兼容推导。

H5 测试覆盖：

- 详情类型包含 `nodeProgress`。
- 全节点进度组件展示五种状态、节点类型和节点下多任务。
- 无 `nodeProgress` 时回退旧任务列表。
- 工作流模块结构检查防止重新只遍历 `tasks`。

最终运行后端全量测试、H5 工作流结构检查、目标文件 lint、TypeScript 类型检查、H5 构建，并在具备登录态时验证桌面和移动端历史详情。
