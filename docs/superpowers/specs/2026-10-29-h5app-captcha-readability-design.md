# H5App 登录验证码清晰度优化设计

## 目标

在不降低当前验证码干扰强度的前提下，提高钉钉 H5 账号密码登录验证码的人工可读性。线上生成结果应稳定达到或优于已确认的 A 方案，不再因画布过小或前端裁切导致字符难以辨认。

## 后端生成

- 继续使用五位验证码和当前排除易混淆字符的字符集。
- 保留 `2` 组噪点以及正弦线、黏液线两类干扰线。
- 生成画布由 `150×48` 调整为 `180×56`，使字符与干扰线拥有更充分的绘制空间。
- 固定使用内置 `RitaSmith.ttf` 可读字体，避免随机选中空心、条纹或立体装饰字体导致字符不可辨认。
- Redis 摘要存储、两分钟有效期、一次性消费和大小写不敏感校验保持不变。

## H5App 展示

- 桌面端验证码图片由 `110×40` 调整为 `128×44`。
- 图片使用完整适配，不再使用 `aspectFill` 裁切验证码边缘。
- 移动端继续与输入框、刷新按钮保持单行布局，并保证输入区域可用。
- 验证码图片继续支持点击和键盘刷新，不新增独立刷新按钮。

## 验证标准

- 后端测试固定校验画布尺寸、噪点数量、干扰线类型、验证码长度和字符集。
- 连续生成多张验证码进行视觉抽样，不能只以单张图片作为清晰度结论。
- H5 构建后分别检查桌面登录卡片和手机宽度，确认图片无裁切、变形或布局溢出。
- 运行 H5App 的 lint、类型检查、钉钉模块检查、UI 样式检查和 H5 构建。

## 不变范围

- 不修改验证码接口、请求字段、错误语义和开关配置。
- 不改变 Admin 登录验证码与 H5App 共用生成器的事实，因此生成清晰度会同步改善。
- 不降低验证码的服务端安全约束，也不新增第三方依赖。
