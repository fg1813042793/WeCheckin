# H5App 流程历史表单导入设计

## 目标与边界

在 H5App 通用 OA 流程发起页增加“导入”按钮，允许发起人从当前流程定义下自己发起的历史申请中复制表单内容，并支持：

- 按兼容字段全部导入。
- 手工配置“历史字段 → 当前字段”的一对一映射。
- 默认仅填充当前空字段，可选择覆盖本次映射命中的已有内容。
- 导入前预览实际变化、跳过字段和兼容性提示。

本期只处理 `h5app/` 通用工作流，不修改绩效考评业务流程，不支持跨流程定义选择历史表单，也不新增历史表单模板库。

导入只修改当前浏览器中的未提交表单状态，不直接写数据库、不修改历史实例。保存草稿或正式提交时继续使用现有接口和后端表单校验。

## 方案选择

采用前端导入方案，复用现有接口：

- `GET /api/v2/dingtalk/h5/workflows/instances`：分页查询当前用户在当前流程下的历史申请。
- `GET /api/v2/dingtalk/h5/workflows/instances/:id`：读取历史实例绑定发布版本的表单 Schema 和 `formData`。

不新增专用导入接口。后端已有实例访问控制仍是历史数据读取的安全边界，当前表单在正式发起时仍按当前发布版本重新校验和计算。

## 权限

新增按钮权限：

```text
dingtalk_h5:button:workflow:history-import
```

名称为“导入历史表单”，父级为 `dingtalk_h5:menu:workflow`。

导入按钮同时要求：

- `dingtalk_h5:button:workflow:history-import`
- `dingtalk_h5:api:workflow:start`
- `dingtalk_h5:api:workflow:view`
- 当前用户在当前流程定义的允许发起范围内

权限迁移将已有 `dingtalk_h5:api:workflow:start` 的有效 allow 授权复制为按钮授权。没有流程查看权限时，即使拥有按钮权限也不能显示或读取历史实例。

不新增 API 权限；列表、详情和提交继续经过现有 API 权限中间件。

## 入口与交互

### 发起表单入口

在发起审批表单卡片顶部增加“导入”图标按钮，与表单标题和必填提示保持同一工具栏。按钮只在当前流程加载完成、允许发起且权限满足时显示。

点击后打开历史表单导入弹窗，不切换到“历史记录”页签，不清空当前表单，也不影响草稿状态。

### 弹窗布局

弹窗分为三部分：

1. 历史申请选择。
2. 导入方式和字段映射。
3. 导入预览和确认操作。

PC 使用居中弹窗，最大宽度约 760px；移动端使用底部全宽弹层，内容区可滚动，确认操作固定在底部。弹窗不嵌套页面卡片。

### 历史申请选择

默认按发起时间倒序加载当前定义、当前用户发起的实例，显示：

- 单据标题
- 流程单号
- 审批状态
- 流程版本
- 发起时间
- 完成时间

支持按标题搜索、状态筛选和分页。所有未删除状态均可选择，包括审批中、已完成、已驳回、已撤回和已取消；状态在列表中明确展示。

选择实例后请求详情，并以详情返回的历史 `form` 和 `formData` 作为导入源。历史实例的 Schema 来自其绑定发布版本，不使用当前流程 Schema 反推历史字段。

## 导入方式

### 全部导入

“全部导入”只按稳定字段 `key` 自动匹配：

1. 历史字段和当前字段 key 相同。
2. 字段类型兼容。
3. 当前发起节点对目标字段拥有 `write` 权限。
4. 目标字段不是计算字段或布局组件。

全部导入不按标签自动猜测字段，避免不同业务含义但名称相同的字段被误覆盖。字段改名或 key 变化时使用“字段映射”。

### 字段映射

映射表每行包含一个历史字段和一个当前字段：

```text
历史字段 → 当前字段
```

规则如下：

- 一个源字段最多使用一次。
- 一个目标字段最多被写入一次。
- 目标下拉框只展示类型兼容且当前可写的字段。
- 初次进入映射模式时，先按相同 key 推荐，再按唯一的相同标签和兼容类型推荐。
- 相同标签存在多个候选时不自动选择。
- 支持增加、删除和清空映射行。

映射改变后立即重新生成预览，不直接修改发起表单。

## 字段范围与类型兼容

表单组只负责布局，导入时递归展开组内数据字段。标签、说明和按钮不是数据字段，不参与导入。

当前目标字段范围取当前发起节点 `write` 权限。隐藏、只读和计算字段不能作为目标字段；计算字段在导入完成后按当前定义重新计算。

兼容规则：

| 类型组 | 兼容范围 |
| --- | --- |
| 文本 | `text`、`textarea`、`phone`、`email` 之间兼容 |
| 数值 | `number`、`amount` 之间兼容 |
| 单选 | `select`、`radio` 之间兼容 |
| 多选 | `multi_select`、`checkbox` 之间兼容 |
| 日期时间 | `date`、`datetime`、`time`、`date_range` 只允许相同类型 |
| 人员 | `user`、`user_multi` 分别只允许相同类型 |
| 部门 | `department`、`department_multi` 分别只允许相同类型 |
| 其他 | `boolean`、`attachment` 只允许相同类型 |
| 明细表 | 只允许 `detail_list → detail_list`，且列 key 和列类型兼容 |

选项字段处理：

- 当前字段使用静态选项时，单选值不存在则跳过该字段；多选只保留当前仍存在的选项，并在预览中提示被过滤项。
- 当前字段使用后端接口动态选项时，导入预览标记为“动态选项待确认”；保留类型正确的历史值，由当前控件加载选项后展示，正式提交仍执行现有校验。

附件导入复制附件元数据引用，不重新上传文件。历史实例访问权和现有静态资源访问规则保持不变。

明细表作为一个顶层字段映射。兼容性要求目标列均能在源列中按相同 key 找到兼容字段；导入时按目标列重新构建行、生成目标行 ID，并丢弃源表中目标不存在的列。暂不提供逐列手工映射。

## 空值与覆盖规则

以下值视为空：

- `undefined`
- `null`
- 空字符串或只包含空白的字符串
- 空数组

数字 `0`、布尔值 `false` 和包含行的明细表不是空值。

默认关闭“覆盖已有内容”：

- 目标字段为空时导入。
- 目标字段已有值时保留当前值，并在预览中标记“保留现有内容”。

开启“覆盖已有内容”后：

- 只覆盖本次有效映射命中的目标字段。
- 未映射字段始终保留。
- 不兼容或无效字段仍然跳过，不因开启覆盖而强制写入。

## 预览与应用

预览按目标字段展示：

- 字段名称
- 当前值摘要
- 导入值摘要
- 处理结果：将导入、将覆盖、保留现有、类型不兼容、选项已过滤、动态选项待确认

预览顶部显示统计：

- 可导入字段数
- 将覆盖字段数
- 保留字段数
- 跳过字段数

没有任何可导入字段时禁用确认按钮。

点击“确认导入”后：

1. 按预览结果生成目标字段补丁。
2. 与当前 `formData` 合并。
3. 使用当前表单 Schema 执行值规范化和计算字段重算。
4. 关闭弹窗并提示导入数量。
5. 触发现有未保存状态，页面关闭时继续使用草稿保护逻辑。

取消弹窗不修改当前表单。

## 前端模块边界

新增纯函数模块 `workflow-history-import.ts`，负责：

- 展平历史和当前数据字段。
- 判断字段类型兼容性。
- 生成全部导入映射。
- 生成字段映射建议。
- 校验一对一映射。
- 规范化导入值。
- 生成预览结果和最终补丁。

新增 `WorkflowHistoryImportDialog.vue`，只负责历史实例选择、映射编辑、覆盖开关和预览交互。它通过 props 接收当前定义、字段权限和当前表单数据，通过事件返回最终补丁，不直接操作 Pinia 或提交流程。

`WorkflowStartPage.vue` 负责：

- 判断按钮权限。
- 控制弹窗显隐。
- 把导入补丁合并到当前 `formData`。
- 重新初始化当前表单值并更新未保存状态。

现有 `WorkflowDetailPanel` 的“再次提交/修改申请”继续使用 `WorkflowStartSeed`，不与导入弹窗耦合。

## 后端与数据

不新增业务表、不修改流程实例数据模型、不增加专用导入 API。

新增版本化权限迁移：

- 注册 `dingtalk_h5:button:workflow:history-import`。
- 从已有 `dingtalk_h5:api:workflow:start` 的有效 allow 授权回填按钮权限。
- 使用幂等插入和授权更新。

历史实例列表继续使用 `scope=started + definitionId`，后端强制按当前登录用户限制发起人范围。详情接口继续校验实例访问权。导入来源实例 ID 不写入新流程变量或历史；本期只把它视为前端复制来源。

## 错误处理

- 历史列表加载失败：保留弹窗并显示重试。
- 实例详情加载失败或无权访问：不进入映射步骤。
- 历史实例已删除：提示“历史申请不存在或已删除”。
- 当前流程在弹窗打开期间刷新版本：关闭弹窗并提示重新选择，避免按旧目标 Schema 应用。
- 没有兼容字段：展示原因并禁用确认。
- 导入值规范化失败：只跳过对应字段，并在预览中显示原因。
- 动态选项加载失败：字段标记待确认，不阻止其他字段导入。

## 兼容性

- 历史实例缺少部分当前字段时只跳过，不生成默认覆盖。
- 当前定义新增字段保持当前默认值或用户已填值。
- 当前定义删除字段时历史多余数据不会写入当前表单。
- 历史附件字符串数组和当前附件对象数组继续复用现有附件规范化逻辑。
- 历史定义不存在导入配置时不受影响，因为导入能力属于发起页通用功能，不写入流程定义。

## 验证

- 纯函数单元/结构检查覆盖类型兼容、同 key 全量映射、同标签建议、重复目标拒绝、空值判断、覆盖策略、选项过滤、明细表兼容和计算字段排除。
- H5 结构检查覆盖按钮权限、弹窗接线、历史列表与详情 API 复用、导入后合并和重算。
- 权限目录及迁移测试覆盖按钮权限注册和历史 start 授权回填。
- 运行 H5App `pnpm lint`、`pnpm type-check`、工作流检查和 H5 构建；既有基线失败单独报告。
- PC 手工验证全部导入、字段映射、覆盖开关、搜索分页和弹窗布局。
- 手机端手工验证底部弹层、滚动、固定操作区和窄屏文本不溢出。
- 验证导入后保存草稿、恢复草稿、提交新流程和关闭页面未保存提示。

## 非目标

- 不支持跨流程定义导入。
- 不支持从其他用户的申请导入。
- 不提供明细表逐列手工映射。
- 不把历史表单保存为公共或个人模板。
- 不修改历史流程实例或原表单数据。
- 不记录导入来源到新流程实例审计。
- 不修改现有绩效业务流程。
