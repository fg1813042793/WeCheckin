# 流程明细字段预览对齐修复设计

## 背景

流程表单设计器的明细字段预览将所有字段名称放在一个 24 栅格网格中，再将所有输入占位放在另一个 24 栅格网格中。当明细列使用不同宽度并发生换行时，名称会先全部排完，输入框才开始排布，导致名称和对应输入框失去直接的上下关联。

运行态表单已经采用“每个列单元同时包含名称和输入控件”的结构，不存在该问题。

## 目标

- 每个明细子字段名称紧贴在自己的输入框预览上方。
- 保留现有 24 栅格列宽配置以及字段顺序。
- 普通明细字段和分组内明细字段的预览表现一致。
- 不修改流程表单数据、API、后端校验、运行态表单或已发布流程定义。

## 决策

采用局部结构修复，不新增共享组件：

1. 将明细预览中的独立名称网格和输入网格合并为一个列网格。
2. 每个明细列渲染一个 `detail-preview__cell`，列宽作用于该单元。
3. 单元内部按垂直方向依次渲染 `detail-preview__label` 和 `detail-preview__control`。
4. 同步修改 `WorkflowFormDesigner.vue` 与 `WorkflowFormFieldPreview.vue`，覆盖根级字段和分组内字段。

不抽取新组件，因为两处预览的外围职责和可用辅助函数不同，本次只修复一小段结构。也不使用 CSS `subgrid` 连接原有双网格，以避免额外兼容性和维护成本。

## 样式

- `detail-preview__grid` 保持 `repeat(24, minmax(0, 1fr))`。
- `detail-preview__cell` 使用纵向布局和稳定间距，名称、输入框随同一个网格单元换行。
- 标签保持现有小号、加粗、弱化颜色。
- 输入预览保持现有高度、边框、圆角和背景。
- 不改变“新增行”按钮的位置和状态。

## 测试

1. 在 `check-workflow-form-designer.mjs` 中增加结构断言，要求两套预览都包含 `detail-preview__grid`、`detail-preview__cell`、`detail-preview__label` 和 `detail-preview__control`，并禁止旧的 `detail-preview__head`、`detail-preview__row`。
2. 先运行结构检查并确认旧实现失败，再实施最小模板和样式修改。
3. 运行 `npm run check:workflow-form-designer`。
4. 运行 `npm run check:all`。
5. 启动 Admin，在浏览器中复现包含 24、12、12、24 混合列宽的明细字段，验证桌面和窄窗口下每个名称都紧贴对应输入框，并检查控制台和框架错误覆盖层。

## 成功标准

- 用户截图中的“目标、权重、完成度、结果”分别与自己的输入框直接上下对应。
- 列宽和换行顺序保持为 24、12、12、24。
- 普通明细和分组内明细均通过结构检查和浏览器验证。
- Admin 全量检查通过，或如实记录与本次改动无关的既有失败。
