# 工作流流程配置与允许发起时间设计

## 1. 目标

在通用工作流设计器中新增“流程配置”页签，集中维护发布时生效的流程级配置：

- 允许发起范围。
- 允许发起时间。

发布弹窗只确认流程名称和目标版本，不再重复编辑流程配置。配置随草稿保存，并在发布时固化到新的流程定义版本中。

本功能只修改独立通用工作流模块，不修改现有绩效业务流程。

## 2. 配置归属

发起范围和发起时间都属于开始节点配置，但统一通过“流程配置”页签编辑。开始节点抽屉和发布弹窗不再提供重复入口，避免出现多份配置源。

旧发布版本没有发起时间配置时按“长期有效”处理。草稿修改不影响已经发布的版本或运行中的流程实例。

## 3. 允许发起时间

允许发起时间使用四种互斥模式：

- `always`：长期有效。
- `fixed`：一次性的开始、结束时间段。
- `weekly`：每周指定星期和每天时间段周期开放。
- `monthly`：每月指定日期和每天时间段周期开放。

周期模式统一使用 `Asia/Shanghai` 时区，并可选配置生效开始日期和生效结束日期。开始边界包含，结束边界不包含。

每周模式允许多选星期，使用 `1` 至 `7` 表示周一至周日。每月模式允许多选 `1` 至 `31` 日，并提供独立的“最后一天”选项；选择 `31` 日时，没有 31 日的月份直接跳过，只有选择“最后一天”才在短月月末开放。

第一版每天只支持一个时间段，并要求结束时间晚于开始时间，不支持跨午夜时间段。

## 4. 数据模型

开始节点新增 `availability`：

```json
{
  "mode": "weekly",
  "timezone": "Asia/Shanghai",
  "effectiveStartDate": "2026-09-01",
  "effectiveEndDate": "2026-12-31",
  "weekdays": [1, 3, 5],
  "dailyStartTime": "09:00",
  "dailyEndTime": "18:00"
}
```

固定时间段使用 Unix 毫秒：

```json
{
  "mode": "fixed",
  "timezone": "Asia/Shanghai",
  "startsAt": 1788224400000,
  "endsAt": 1788310800000
}
```

月度模式使用 `monthDays` 和 `lastDayOfMonth`。所有列表必须使用合法、唯一值；日期使用 `YYYY-MM-DD`，每日时间使用 `HH:mm`。

## 5. 运行时语义

允许发起时间只限制创建新的流程实例：

- 客户端用户自行发起时校验。
- 管理员代用户发起和批量按用户独立发起时校验。
- 已创建的草稿在真正提交并创建实例时重新校验。
- 已运行的流程实例不受窗口关闭影响。

流程列表和详情返回当前时间状态，用于调用端展示“可发起、未开始、已结束、当前未开放”；正式发起接口在事务内读取实际发布版本并再次校验，后端结果为最终依据。

## 6. 页面交互

设计器页签顺序调整为：

1. 表单设计
2. 流程设计
3. 字段权限
4. 流程配置

“流程配置”页面分为“允许发起范围”和“允许发起时间”两个全宽区域。范围继续支持全部用户，或指定部门与额外用户的并集。时间模式使用分段单选；周/月周期使用星期或日期多选、时间范围和可选生效日期范围。

只读用户可以查看配置但不能修改。切换模式时只保留当前模式需要的字段，避免隐藏的旧值参与发布。

## 7. 校验与错误

- 指定范围没有部门和用户：`initiator_invalid`。
- 时间模式或字段组合无效：`start_availability_invalid`。
- 固定窗口尚未开始：提示“流程尚未到允许发起时间”。
- 固定窗口或周期有效期已经结束：提示“流程已超过允许发起时间”。
- 周/月周期当前不在开放日或开放时段：提示“当前不在流程允许发起时间内”。

发布前执行完整定义校验，流程配置错误会定位到“流程配置”页签。

## 8. 非目标

- 不支持一天内多个开放时间段。
- 不支持跨午夜时间段。
- 不接入法定节假日或调休日历。
- 不允许同时组合每周和每月规则。
- 不修改现有绩效业务流程。
