# 通用工作流表单布局与说明组件设计

## 1. 目标与范围

在现有独立通用 Go 工作流模块和管理端表单设计器中增加布局与说明能力，使设计者可以把业务字段组织成清晰的分组，并向发起人、审批人和办理人提供不参与数据提交的标签、静态说明和说明按钮。

本次改动只扩展通用 workflow 定义、admin 表单设计器和通用工作流运行时，不修改现有绩效业务流程。

首版包含：

- 固定表单组容器 `group`。
- 静态标签 `label`。
- 静态说明 `description`。
- 说明按钮 `button`。
- 表单组和普通数据字段的可选说明按钮。

首版不包含：

- 表单组折叠。
- 表单组内继续嵌套表单组。
- 按钮跳转链接、调用接口、执行脚本或修改表单值。
- HTML 或富文本说明内容。
- 展示组件的节点级字段权限。

## 2. 定义数据模型

### 2.1 新增字段类型

`WorkflowFormFieldType` 和 Go `FormField` 类型集合增加：

- `group`：表单组容器。
- `label`：静态标签。
- `description`：静态多行说明。
- `button`：打开说明对话框的独立按钮。

`FormField` 增加以下可选属性：

```json
{
  "fields": [],
  "content": "说明文本",
  "help": {
    "buttonText": "查看说明",
    "title": "金额填写说明",
    "content": "请填写本次实际金额。"
  }
}
```

- `fields`：仅 `group` 使用，保存组内字段和展示组件。
- `content`：仅 `description` 使用，保留用户输入的换行。
- `help`：`group`、普通数据字段和 `button` 可使用。

`label` 使用现有 `label` 字段作为展示文本。`button` 使用现有 `label` 字段作为按钮文字，并必须提供 `help.title` 和 `help.content`。

### 2.2 分组与表单数据

表单组只建立布局层级，不改变业务数据结构。组内普通字段仍以自己的 `key` 写入 `formData` 根级，不写入 `formData[group.key]`。

例如：

```json
{
  "type": "group",
  "key": "basic_info_group",
  "label": "基本信息",
  "fields": [
    { "type": "text", "key": "applicant_name", "label": "申请人" },
    { "type": "number", "key": "amount", "label": "金额" }
  ]
}
```

对应提交数据仍为：

```json
{
  "applicant_name": "张三",
  "amount": 1200
}
```

这保持现有 `formPermissions`、实例表单数据、任务表单补丁和历史发布版本的数据语义。

### 2.3 唯一标识

所有根级组件和表单组直接子组件都必须具有非空 `key`，且在整个表单布局范围内唯一。`detail_list.columns` 的列 `key` 仍按现有规则在各自明细列集合内唯一，不与根级业务字段共用数据路径。

## 3. 设计器交互

### 3.1 组件面板

左侧“字段组件”增加“布局与说明”分类，包含表单组、标签、说明和按钮。

- 表单组默认名称为“新建分组”，默认占满一行。
- 标签默认文本为“标签文本”。
- 说明默认文本为“请输入说明内容”。
- 按钮默认文本为“查看说明”。

### 3.2 表单组与拖拽

表单组在设计画布中以带标题栏的固定容器展示。组内存在独立拖拽区域，普通字段、标签、说明和按钮可以在根级与分组之间拖动。

- 拖动表单组时，组内组件随整组移动。
- 表单组不能拖入另一个表单组。
- 删除空分组直接执行；删除含子组件的分组前，弹窗确认将同时删除组内组件。
- 字段在根级与分组间移动时保持原 `key`，因此现有节点字段权限继续有效。

### 3.3 属性面板

表单组属性包含标题和可选的说明按钮。普通数据字段属性增加“说明按钮”开关，开启后配置：

- 按钮文字，默认“查看说明”。
- 弹窗标题，默认使用当前字段或分组名称。
- 说明内容，使用多行纯文本输入。

独立按钮必须配置按钮文字、弹窗标题和说明内容。标签和说明组件不再附加说明按钮，避免展示组件嵌套重复语义。

## 4. 运行时展示

### 4.1 分组与展示组件

通用运行时表单递归渲染表单组。表单组以固定标题栏和内容区域展示，不提供折叠。标签显示为组内或根级小标题，说明显示为保留换行的静态文本，独立按钮使用 Element Plus 按钮。

展示组件不读写 `modelValue`，不改变表单数据，在发起、审批、办理和只读详情场景中保持一致。

### 4.2 说明按钮

普通字段的说明按钮放在字段标签之后，使用可识别的文字链接按钮，不仅显示信息图标。表单组的说明按钮放在标题栏右侧。

点击表单组、普通字段或独立按钮的说明入口时，共用同一个 Element Plus 对话框：

- 标题使用 `help.title`。
- 内容使用 `help.content` 并保留换行。
- 内容只按文本渲染，不使用 `v-html`。
- 对话框只提供关闭操作，不产生业务副作用。

## 5. 数据、权限与可见性

表单数据初始化、读取和校验递归访问表单组内字段，并忽略 `group`、`label`、`description` 和 `button` 本身。

字段权限设计器展平根级和表单组内的真实业务字段：

- 表单组和展示组件不出现在字段权限列表中。
- 组内 `detail_list` 仍作为一个顶级业务字段配置读写权限和行增删动作。
- 任务运行时按已有 `formPermissions` 过滤组内数据字段。
- 展示组件在各节点始终可见，用于提供统一的业务上下文。
- 当分组内没有展示组件，且所有业务字段均因权限隐藏时，运行时不渲染空分组。

## 6. 后端校验与错误处理

`ValidateDefinition` 递归校验表单组定义，并增加以下规则：

- `group`、`label`、`description` 和 `button` 都必须有非空且唯一的 `key`。
- `group.label` 必填，`group.fields` 至少包含一个子组件。
- `group.fields` 中不允许再出现 `group`。
- `label.label` 必填，最长 100 个字符。
- `description.content` 必填，最长 2000 个字符。
- `button.label` 必填，最长 30 个字符，并必须配置有效 `help`。
- `help.buttonText` 可选，缺省时运行时显示“查看说明”，最长 30 个字符。
- `help.title` 必填且最长 100 个字符，`help.content` 必填且最长 2000 个字符。
- `fields`、`content` 和 `help` 出现在不支持的字段类型上时返回明确的表单定义校验错误。

设计器允许保存未完善的草稿，现有“校验”和“发布”流程会阻止无效表单定义进入新版本。管理端根据校验错误聚焦到表单设计页签和对应组件。

运行时只使用已发布并校验通过的定义。若历史或外部数据意外缺失说明内容，说明按钮不打开空对话框，也不影响其他表单字段。

## 7. 兼容性与发布版本

新增属性都使用 `omitempty` 和前端可选属性，旧定义无需数据迁移。已发布实例继续绑定自身 `DefinitionID + DefinitionVersion`，不会因新设计器组件改变历史展示或审批数据。

发布定义的深拷贝必须递归复制 `fields` 和 `help`，避免草稿后续编辑污染已发布版本。BPMN 仍只表达流程节点与连线，表单布局和说明组件不生成额外 BPMN 元素。

## 8. 测试与验收

后端自动化覆盖：

- 有效的表单组、标签、说明、独立按钮和字段说明配置。
- 重复 `key`、空内容、无效说明、非法组嵌套和属性误用。
- 表单数据校验递归访问组内业务字段，并忽略展示组件。
- 节点表单补丁按组内字段权限执行。
- 发布定义深拷贝保持分组和说明数据隔离。

管理端自动化覆盖：

- 布局与说明组件面板及属性编辑。
- 根级与分组间拖拽，以及禁止分组嵌套。
- 删除分组和权限字段集合更新。
- 发起、审批、办理和只读场景的分组渲染。
- 字段标签后的文字说明按钮、分组按钮、独立按钮和共用对话框。
- 展示组件不进入提交数据和字段权限列表。

完成后运行 workflow 后端定向测试、admin 工作流静态回归检查、admin 完整构建和变更文件格式检查。最终页面拖拽和弹窗交互由用户手工验收。
