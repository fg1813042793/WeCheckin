# 工作流发起范围统一组织树与排除用户设计

## 1. 目标

优化独立通用工作流设计器的“流程配置”，将指定发起部门和指定发起用户合并为一个组织树选择器，并增加排除用户能力。本功能不修改现有绩效业务流程。

## 2. 配置语义

开始节点发起配置使用以下结构：

```json
{
  "scope": "specified",
  "userIds": [12, 18],
  "departmentIds": [3, 7],
  "excludedUserIds": [21]
}
```

- `scope: all`：除 `excludedUserIds` 外的全部有效用户可发起；此时 `userIds`、`departmentIds` 必须为空。
- `scope: specified`：`userIds` 与 `departmentIds` 构成允许范围并集，且至少一类非空。
- `excludedUserIds` 在两种模式下都生效，优先级最高。即使用户位于 `userIds` 或属于 `departmentIds`，仍不得发起。
- 部门按用户发起时的实时部门关系匹配，只包含明确勾选的部门本身，不自动包含子部门。
- 允许列表与排除列表允许重叠，由排除优先规则消除歧义。
- 历史定义未包含 `excludedUserIds` 时按空列表处理，行为不变。

## 3. 设计器交互

- “指定范围”下仅显示一个“允许发起范围”组织树。
- 组织树同时允许独立勾选部门和用户；勾选部门保存为 `departmentIds`，不会展开并固化为用户 ID；勾选用户保存为 `userIds`。
- “排除用户”在“全部用户”和“指定范围”下都显示，复用用户树选择器并保存为 `excludedUserIds`。
- 选择结果在输入框内紧凑显示，超出宽度的项目显示为 `+N` 并支持悬停查看。

## 4. 运行时判定

统一判定顺序：

1. 发起用户位于 `excludedUserIds` 时立即拒绝。
2. `scope != specified` 时允许。
3. 发起用户位于 `userIds` 时允许。
4. 用户当前任一所属部门位于 `departmentIds` 时允许。
5. 其他情况拒绝。

客户端可发起列表、定义详情、正式发起和管理员代发均复用该规则。管理员页面和定时任务中的候选发起人列表同步隐藏排除用户，但后端仍执行最终鉴权。

## 5. 兼容性与验证

本次只扩展流程定义 JSON，不修改数据库表结构，不提升定义 Schema 版本。验证覆盖核心定义校验、发布复制、持久化映射、运行时列表/详情/发起鉴权、管理端候选人过滤、设计器回显与交互、跨端类型和历史定义兼容性。
