## Goals / Non-Goals

**Goals:**
- 统一 Tag 命名规范：`@Tags 客户端, 模块名` / `@Tags PC端, 模块名`
- 去掉模块名中的"-客户端"后缀（如"赛事活动-客户端"→"赛事活动"）
- 特殊接口归入合适的分类

**Non-Goals:**
- 不修改任何 API 路由或业务逻辑
- 不改变 swag init 的生成配置

## Decisions

1. **纯 replaceAll 替换** — 大部分 Tags 分两类模式，直接用 replaceAll 替换效率最高
2. **"表单工具"归属** — 客户端侧的 2 个表单工具接口（validate/apply）归入`客户端, 表单工具`；管理端侧保持`PC端, 表单工具`
3. **"报名"归属** — `// @Tags 报名`（无分类）改为`// @Tags 客户端, 报名`
4. **"赛事活动-客户端" → "赛事活动"** — 去掉"-客户端"后缀，统一命名

## Risks / Trade-offs

- 修改后需重新生成文档验证 Tags 是否生效
- 前端若依赖已有 Tag 名称筛选接口，需要同步更新
