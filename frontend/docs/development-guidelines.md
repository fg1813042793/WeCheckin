# Frontend 开发规范

## 1. 适用范围

本文档适用于 `frontend/` 下的 uni-app 客户端，包括 H5、App 和微信小程序。同时遵守 [WeCheckin 统一开发规范](../../docs/development-guidelines.md) 和 [API v2 接口说明](../../docs/API_V2.md)。

`frontend` 与 `h5app` 是两个独立前端：`frontend` 继续使用当前根目录式 JavaScript/uni-app 结构；`h5app` 是 TypeScript + uView Pro 的钉钉 H5 权威源。不在一个局部需求中把两套工程结构直接混用。

## 2. 技术与工具基线

- uni-app、Vue 3、Vite，源码根目录由 `UNI_INPUT_DIR=.` 指定。
- 包管理使用 npm，依赖变更同步 `package-lock.json`，不与 pnpm/yarn lockfile 混用。
- 当前没有 ESLint 或 TypeScript 类型检查脚本；必须使用现有 `check:*` 和平台构建，不声称已有不存在的 lint/类型门禁。

## 3. 目录职责

- `pages/`：uni-app 页面，按业务域分目录。新页面必须同步 `pages.json`。
- `components/`：跨页面复用组件；FormKit、问卷等大业务域按子目录组织。
- `api/`：客户端和移动端管理功能的 API 封装，页面不直接散落请求路径。
- `config/`：API 地址、版本和公开运行配置。密钥不得放入前端配置。
- `utils/`：请求、认证、格式化和纯工具函数。
- `mixins/`：旧页面仍共享的 mixin 逻辑。新代码优先使用明确函数/组件复用，不为局部功能扩大隐式 mixin 依赖。
- `static/`：图片、图标、字体和 tabbar 资源。
- `uni_modules/`：uni-app 插件模块。修改第三方或通用模块前确认升级和多端影响。
- `dist/` 和 `unpackage/` 是构建产物，不手工编辑或提交。

## 4. Vue 页面与组件

- 修改现有页面时保持局部 Vue 3 写法和数据流，不在功能修复中重写整个页面。
- 页面负责导航参数、加载流程和页面级状态；可复用的展示、表单、列表项和业务逻辑拆到组件或工具。
- props、events 和字段命名在同一业务域保持一致，避免组件为兼容多套临时字段而长期分支。
- 列表项使用稳定 key，不在模板渲染期执行昂贵转换或发起请求。
- 页面销毁时清理 timer、listener、临时上传、请求状态和其他外部副作用。

## 5. API、认证与存储

- 新客户端请求只使用 `/api/v2/*`。旧 `/passport`、`/home`、`/survey`、`/exam` 等路径仅作历史兼容。
- 请求统一经过 `api/` 和公共请求工具，base URL、token、超时、通用错误和登录失效统一处理。
- 页面只对可恢复业务错误展示针对性操作，避免请求层和页面重复 toast。
- 并发请求需要识别过期响应、重复请求和快速切换页面。搜索、分页和刷新不得让旧响应覆盖新状态。
- 只持久化必要、可序列化、非敏感状态。普通业务操作不调用全局 `clearStorage`，退出登录也应保留与账号无关的合法本地设置。

### 删除语义

- `frontend` 面向普通客户端用户，页面中的单条删除、批量删除、撤销后删除等操作必须调用客户端软删除接口；后端只更新删除标记和审计字段，不物理移除业务记录。
- 软删除后的记录不再出现在普通列表和详情入口中，但必须保留业务数据、关联关系、流转记录和历史版本，不能仅由前端从本地列表隐藏来代替后端删除。
- 删除权限、记录归属、当前状态和重复删除必须由后端校验；前端根据接口结果更新页面，不自行构造删除状态或调用 `/api/v2/admin/*` 接口。
- 管理后台 `admin` 中的删除属于物理删除，由 `/api/v2/admin/*` 接口独立实现。客户端软删除和后台物理删除不得复用为同一个无差别删除接口。
- 新增删除能力时必须在 API 文档和类型中明确 `soft delete` 或 `physical delete`，并覆盖已删除记录不可见、重复删除、无权限和关联历史保留等场景。

## 6. uni-app 跨端规则

- 优先使用 `uni.*` API 和 uni-app 组件，不在共享代码中无条件使用 `window`、`document`、微信、App 或原生平台 API。
- 平台专属能力使用 uni-app 条件编译注释隔离，并为其他平台提供合理降级或明确不支持反馈。
- 常规移动布局使用 `rpx` 和 flex，只对细边框、固定像素资源或平台约束使用 `px`。
- 页面跳转使用 `uni.navigateTo`、`uni.redirectTo`、`uni.switchTab` 或 `uni.reLaunch`，目标路径必须在 `pages.json` 中声明。
- 修改 `pages.json`、`manifest.json`、平台权限、原生插件或条件编译时，至少构建和验证目标平台。

## 7. 移动端 UI 与状态

- 复用项目现有色彩、间距、组件和页面布局，不在单个页面引入独立设计系统。
- 页面覆盖加载、空、断网/超时、无权限、禁用、提交中和成功反馈。
- 长文本、表单项、按钮和列表在窄屏、大字号和输入法弹出时不溢出或遮挡后续内容。
- 底部操作、tabbar 和弹窗考虑安全区，滚动容器不与页面滚动互相争抢。
- 相机、位置、文件、剪贴板和通知等设备能力要处理拒绝权限、不支持和调用失败。

### PC 端选择与日期控件

- PC H5 的普通单选项必须在字段附近直接下拉，不得使用移动端底部弹层式选择器。
- 日期及日期范围使用日历式交互；PC H5 优先使用锚定日历或原生 `input[type=date]`，不用底部滚轮或普通列表代替。
- 共享页面必须为 App/小程序保留适配分支；使用原生 H5 `select` 或 `input[type=date]` 时，需注明原因并统一焦点、禁用、边框和尺寸样式。

## 8. 资源、配置与日志

- 静态资源放在 `static/` 的对应分类目录，避免在页面目录散落大图或重复资源。
- API 地址由环境变量或 `config/` 统一解析，真机环境使用设备可访问的测试/局域网地址。
- 页面和组件不保留调试 `console` 输出。生产环境不输出 token、完整用户数据或请求体。
- 不直接修改 `dist/` 或 `unpackage/` 定位问题；回到源码修改并重新构建。

## 9. 验证命令

当前稳定静态检查：

```bash
cd frontend
npm run check:all
```

目标平台构建：

```bash
cd frontend
npm run build:h5
npm run build:app
npm run build:mp-weixin
```

只运行受影响平台的必要构建，但修改条件编译、共享请求层或公共组件时应扩大验证范围。

页面、导航、设备 API、小程序配置或 App 行为变更需要在相应浏览器、开发者工具或真机完成冒烟，不用静态脚本代替可见结果。

## 10. 交付检查

1. 页面、组件、API、配置和工具的职责没有交叉扩散。
2. 新接口使用 `/api/v2`，请求、认证和通用错误处理集中。
3. 平台专属 API 已条件编译，其他平台有明确降级。
4. 加载、空、错误、无权限、安全区和输入法场景已检查。
5. `npm run check:all`、相关平台构建和必要的真机/工具冒烟结果已如实报告。
