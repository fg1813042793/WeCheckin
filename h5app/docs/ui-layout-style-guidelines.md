# H5App UI 布局与样式规范

本规范用于固定 H5App 新页面的布局、响应式、表格、搜索栏和弹窗基线，减少每个页面重复调整样式。以 `src/common/ui-layout.scss` 为可执行样式契约，以本文档为交互和验收契约。

## 基本原则

- 新页面先使用 `app-layout-page`、`app-page-header`、`app-filter-bar`、`app-data-table` 和 `app-dialog-shell` 基线类，再增加业务差异样式。
- 通用尺寸和颜色从 `src/common/ui-layout.scss` 的 `--app-*` 变量取值，业务页不重复定义页边距、控件高度、表头高度和弹窗宽度。
- 按内容容量选择表格、列表或卡片，不为了视觉装饰把每个页面分割成多层卡片。页面区段默认无外层浮动卡片。
- 只有在现有基线无法表达业务结构时才新增公共变量或断点；新增后同步更新本文档和 `check:ui-style`。
- 不使用视口宽度直接缩放字号。文字使用固定层级，容器通过换行、省略或改变排列响应宽度。

## 响应式断点与验证尺寸

| 模式 | 视口宽度 | 布局规则 | 必验证尺寸 |
| --- | --- | --- | --- |
| 手机 | `<= 768px` | 单列，搜索项纵向排列，表格转信息列表，详情弹层使用底部弹层 | `360x800`、`390x844` |
| 紧凑 PC/平板横屏 | `769px - 1023px` | 两列筛选，操作行换行，宽表格允许内部横向滚动 | `800x600`、`1023x768` |
| 标准 PC | `1024px - 1439px` | 默认四列筛选，表格在内容区完整展示 | `1280x720`、`1366x768` |
| 宽屏 PC | `>= 1440px` | 内容最大 `1440px`，五列筛选，不无限拉宽文本列 | `1440x900`、`1920x1080` |

- `768px`、`1024px`、`1440px` 是新页面的默认边界。已有组件的 `900px`、`1200px` 等内容断点可保留，新增时必须说明是由最小列宽或组件交互触发。
- 不只拖拽浏览器目测；涉及布局的交付必须按上表至少验证一个手机尺寸和两个 PC 尺寸。
- 同时使用视口宽度与 `(hover: none) and (pointer: coarse)` 判断触摸交互，不把大屏触摸设备错当成鼠标 PC。

## 页面布局

### 页面容器

- 普通业务页使用 `app-layout-page`，最大宽度 `1440px`，标准 PC 水平边距 `24px`，宽屏 `32px`，手机 `12px`。
- 编辑表单或长文本页叠加 `app-layout-page--form`，最大宽度 `960px`，避免输入行过长。
- 页面内一级区段间距默认 `20px`，手机 `14px`。不使用空白占位节点撑开距离。
- 页面根节点、grid 子项、flex 文本容器必须有 `min-width: 0`，防止输入框、长单词或业务编号撑破容器。

### 页头

- 使用 `app-page-header`，左侧为标题和可选说明，右侧只放页面级主操作。
- PC 标题默认 `24px/700`，手机 `20px/700`；说明文字 `13px`。工作台内不使用营销页尺寸的大标题。
- PC 操作按钮水平排列；手机最多两列，超过两个次要操作收入更多菜单。

### 页面状态

- 加载、空状态和错误状态占用与正常内容相同的主容器，不因文案长度改变页面宽度。
- 空状态不显示空表头加大片空白；使用统一空状态区域，并在有权限时提供唯一主操作。

## 表格页面

### 结构

- 表格页面顺序固定为：页头、搜索/筛选栏、结果摘要或批量操作、数据表格、分页。不在表格上下重复放同一组查询按钮。
- 新表格使用 `app-data-table`，内部为 `app-data-table__scroller`、`__header`、`__row`、`__cell` 和 `__actions`。
- 页面通过 `--app-table-columns` 定义列轨道，通过 `--app-table-min-width` 定义可滚动最小宽度，不在单元格中写绝对定位。

```scss
.order-table {
  --app-table-columns: 160px minmax(220px, 1fr) 140px 120px;
  --app-table-min-width: 760px;
}
```

### 表头与表格行

- 表头高度固定 `44px`，左右内边距 `16px`，字号 `12px`，字重 `600`，背景 `#f7f8fa`，不使用大色块或渐变。
- 普通表格行最小高度 `56px`；包含主副两行信息时可设为 `68px`，但同一张表必须统一。
- 主字段左对齐，数值右对齐，状态和短代码居中，操作列靠右。操作列不随文案长度改变整表列宽。
- 单行文本默认省略，悬停或点击可查看完整值；业务编号不允许挤压状态和操作列。
- 状态只使用语义色：完成/成功为 `success`，待办/处理中为 `warning`，驳回/失败为 `error`，取消/关闭为 `info`。

### 移动端表格

- `<= 768px` 时隐藏表头，每条记录改为单列信息块。每个 `app-data-table__cell` 必须提供 `data-label`，不能依赖 PC 表头才能理解字段。
- 移动端默认显示主标题、状态、时间和主操作；低优先级列隐藏或收入详情，不把 PC 的全部列硬塞入窄屏。
- 只在列具有强比较语义时保留横向滚动，例如统计交叉表；滚动区域不得包含页面级按钮。

## 搜索与筛选栏

- 统一使用 `app-filter-bar`，控件包在 `app-filter-field` 中，标签使用 `app-filter-field__label`，输入组件添加 `app-filter-control`。
- 所有输入、选择、日期和查询按钮高度为 `36px`，圆角 `4px`。同一栏不混用 `32px`、`36px`和 `40px` 控件。
- 标准 PC 默认四列筛选，宽屏五列，紧凑 PC 两列，手机一列。日期范围、组织树选择等宽字段使用 `app-filter-field--wide`。
- 按钮顺序固定为“重置”在前、“查询”在后，查询为主按钮。PC 靠右，手机两列等宽。
- 搜索条件超过四个时可折叠；PC 默认展开，手机默认折叠，折叠标题必须显示已启用条件数。
- 查询中保持表格尺寸稳定，在数据区显示加载态；不隐藏整个筛选栏，不因 loading 文字改变按钮宽度。
- PC 的选择和日期控件遵守主开发规范的“PC 端选择与日期控件”要求，不使用底部滚轮代替 PC 下拉或日历。

## PC 小窗口控件

- `769px - 1023px` 下的 uView Pro 控件使用 `app-pc-control-scope` 公共密度规范，避免 `rpx` 按桌面视口换算后放大。
- 应用壳已将 `app-pc-control-scope` 挂在业务内容区，工作流、绩效和其他内容页默认共享；顶部导航、用户头像和侧边菜单不受影响。
- 流程运行时表单根节点必须同时使用 `app-workflow-form` 和 `app-pc-control-scope`，保证发起页、任务页、抽屉及弹窗中的字段标签、明细列表、选择控件和附件列表共享同一套小窗口密度。
- 业务内容区普通文本以 `14px` 为基准；普通按钮高度为 `36px`，中号 `34px`，小号 `32px`，迷你按钮 `28px`；输入控件高度为 `36px`，输入值及提示文字统一使用 `13px`，同时覆盖 uni-app H5 生成的 placeholder 节点和原生 `::placeholder`。
- 普通图标固定为 `18px`，按钮内图标为 `15px`，空状态等强调图标为 `28px`，加载图标为 `18px` 或 `24px`；不再直接依赖 uView Pro 的 `rpx` 默认值。
- 多行文本的字数统计使用 `11px` 字号和 `16px` 行高，与输入框右侧、底部各保留至少 `6px` 间距，不允许继承 uView Pro 的内联 `rpx` 字号。
- 纯图标按钮使用 `app-icon-button`，默认点击区为 `32x32px`；紧凑操作可叠加 `app-icon-button--small` 使用 `28x28px`。头像、品牌标识和文件缩略图属于业务视觉，由专用 class 维持明确尺寸。
- 使用 `u-popup` 或 `u-modal` 的 PC 业务弹层要在 `custom-class` 中加入 `app-pc-control-scope`，避免 Teleport 后脱离应用壳的公共样式作用域。
- PC 下拉面板打开时必须比较当前视口及滚动容器的上下可见空间；下方不足且上方空间更充足时向上展开，避免面板被页面、弹窗或滚动区域底部裁切。
- 复选框、单选框、开关、状态标签和分页同步使用固定 `px` 尺寸，不在各业务页重复覆盖 uView 内部样式。
- 业务页明确设置的图标按钮、主操作或复杂表单尺寸可继续通过专用 class 覆盖，但必须保持文字和图标不溢出。

## 弹窗与抽屉

### 尺寸和用途

| 类型 | PC 宽度 | 适用场景 |
| --- | --- | --- |
| 小弹窗 | `420px` | 确认、简短输入、单一风险操作 |
| 中弹窗 | `640px` | 常规创建/编辑表单 |
| 大弹窗 | `960px` | 复杂表单、可比较详情 |
| 抽屉 | 视口的 `25% - 40%` | 保留列表上下文的详情浏览，不用于简单创建表单 |

- PC 弹窗居中，最大高度 `min(88vh, 900px)`。手机详情和编辑优先用底部弹层，宽度 `100%`，最大高度 `92vh`，保留底部安全区。
- 使用 `app-dialog-shell`；小弹窗加 `--small`，大弹窗加 `--large`。头、内容、底部分别使用 `__header`、`__body`、`__footer`。
- 只有 `__body` 可滚动，标题、关闭按钮和底部操作保持固定。弹窗内不允许页面和内容同时出现两层垂直滚动条。
- 底部按钮顺序为次要/取消在左，主要/确认在右。危险操作必须用 `error` 语义，不与普通确认按钮同色。
- 关闭按钮使用图标，固定点击区不小于 `32x32px`，并提供无障碍名称。关闭按钮不因标题换行而移位。
- 弹窗上再弹确认框时必须使用 uView Pro 的统一层级管理，禁止在业务组件中临时写大数值 `z-index`。同时只有最上层可响应键盘和点击。
- 抽屉和弹窗必须挂载在可越过应用固定导航的层级；验证遮罩、标题、关闭按钮和底部操作均不被导航遮挡。

## 样式实现约束

- 全局基线只放在 `src/common/ui-layout.scss`，业务页面的专用样式保持 `scoped`。不在多个页面复制同一套表头或弹窗 SCSS。
- 新页面发现基线缺失时，优先补公共变量或基线类，同时评估已有页面；不通过全局标签选择器强制覆盖所有 `view`、`button` 或 `input`。
- 业务状态颜色使用 uView Pro 主题语义变量。中性文字、边框和表面颜色使用 `--app-*` 变量。
- 类名使用业务根 class + BEM；共享基线保留 `app-*` 前缀。不用 `left: 137px` 等页面坐标修复布局。
- 固定导航、底部操作和滚动容器要同时考虑 `env(safe-area-inset-top)` 与 `env(safe-area-inset-bottom)`。

## 新页面验收清单

1. 页面使用统一容器、页头、间距和控件高度，没有重复的通用样式常量。
2. 在 `360x800`、`1024x768` 和 `1366x768` 至少验证一次；宽屏特性再验证 `1920x1080`。
3. 长中文名称、英文长单词、长业务编号、空值和最多按钮数都不撑破容器。
4. 表格表头、行高、对齐、状态色、操作列和手机降级形式符合本规范。
5. 搜索栏在四档宽度下按规则降列，loading 不导致按钮或表格跳动。
6. 弹窗只有内容区滚动，底部按钮可见，层级高于固定导航，手机安全区正确。
7. 鼠标、键盘、触摸、禁用、空状态、失败和无权限状态都有可用反馈。
8. 运行 `pnpm check:ui-style`、`pnpm lint`、`pnpm type-check` 和 `pnpm build:h5`，并记录未覆盖的目标平台风险。
